# 测试修改

本技能迁移自项目已有的 AGENTS.md 规则。原规则继续适用；其形成时的具体案例尚未收集确认，不把这些规则标成已由新案例验证。

## 根据改动选择验证

优先复用已有测试。新增测试应保护长期有价值的行为，避免重复实现细节或固化临时假设。简单文案、排版和显示调整通常检查结果即可；行为缺陷必要时补能捕获原问题的回归测试。

验证范围由改动影响决定。存储、恢复、协议等关键改动应检查相关失败边界；物理按键和剪贴板行为需要实际环境验证，模拟通过不能代替实测。项目的验证方法和已有证据边界见 [验证指南](../../validation.md)，按当前任务查阅相关部分。

## 判断何时停止

临时探针不自动进入永久测试集。相关检查通过后，没有新改动、失败或未解决疑点，不重复或扩大验证。

“尚未验证”说明现有证据的范围，不自动生成补测任务。完成说明应交代本次实际验证了什么，不把离线模拟、真实服务正常返回或工具成功调用扩大为答案质量保证。

## 案例依据

后续优先由用户提供当时的案例。需要另找参考时，先展示具体场景、验证方法如何影响判断以及适用范围，经用户确认后纳入。不得将新找到的相似案例称为上述历史规则的原始出处。

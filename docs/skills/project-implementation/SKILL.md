# 功能代码实现

本技能迁移自项目已有的 AGENTS.md 规则。原规则继续适用；其形成时的具体案例尚未收集确认，提到的参考项目不等于已核对的案例来源。

## 先明确完整使用流程

先明确用户要完成的操作和结果，再实现最小但完整的使用流程。接口可以被调用，只能证明接口可用；是否完成用户任务，要看入口、执行、结果交付和必要的失败处理能否连起来。

保持简单 Python、统一执行核心和清楚的模块职责。优先通用修复，避免为单次情况增加专用分支、不必要的开关和抽象。理解现有边界时按需查阅 [架构说明](../../architecture.md)。

## 根据条件借鉴成熟实现

涉及新能力或设计取舍时，可以参考 pi agent 等成熟实现，但应核实相应机制解决的问题、成立条件以及与当前项目的差异。已有可靠结论可以复用，不要求每次小改重新调研，也不照搬整套能力。

完成验证时使用 [测试修改](../project-testing/SKILL.md)；需要同步文档时使用 [写作与文档修改](../project-writing/SKILL.md)。按实际影响选择，不把这些入口变成每次任务都必须执行的固定流程。

## 案例依据

后续优先使用用户提供的原始案例。需要另找实现参考时，说明具体代码位置、解决的问题和适用条件，并区分已核实机制与推测。新案例及从中归纳的长期原则经用户确认后再固化；日常实现仍按当前任务授权推进。

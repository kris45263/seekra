# 问题发现与修复

本技能迁移自项目已有的 AGENTS.md 规则。原规则继续适用；其形成时的具体案例尚未收集确认，不虚构历史依据。

## 先判断问题是否成立

区分已确认缺陷、待验证疑点和改进建议。选择足以区分可能原因的检查来定位，不因某个假设看起来有可能就增加防御逻辑。

修复当前任务及完成它所必需的关联问题。偶然发现的无关问题简要告知用户，不自动扩展任务或写入长期待办文档。

## 让验证服务于判断

验证用于定位原因和判断修复结果，不为每个小问题启动完整排查流程。涉及测试变更或实际环境验收时，使用 [测试修改](../project-testing/SKILL.md) 判断范围与证据边界。

## 案例依据

后续优先收集用户提供的原始案例，说明当时的现象、排查证据、被排除的原因以及修复为何有效。另行查找的案例先在会话中讨论，经用户确认后纳入；不能把一次问题的处理方法直接规定为所有问题的固定流程。

# 研究发现与已知问题

本文按问题解释证据、当前结论与未知因素。实现契约见 [架构](architecture.md)，测试方法见 [验证指南](validation.md)，具体数据见 [证据索引](../evals/README.md)。以下结论来自有限样本，不代表通用答案质量或长期成功率。

## 版本归因与证据范围

测试问题是：根据 Python 3.13 官方文档，mimalloc 在普通 GIL 与 free-threaded 构建中的捆绑、默认使用、必须使用是否相同？要求来源对应版本。

历史 snippet-only 实验出现把当前 `/3/` 文档表述归给未核实 3.13 页的问题。固定历史增加版本核实提示仍出现过度归因；提供指定页面正文能改变下一步判断，但该实验没有继续到最终答案，不能称为修复。增加 read_page 可使既有核查计划得到执行，也出现过未选择读取或读取后超出预算的情况。

2026-09-10 的自主研究实际读取并续读 3.13 memory 页、读取 free-threading 页，configure 页只读 48000/56562 字符。模型区分了构建支持与运行时默认，但仍有三类可核对问题：

- 把少数已检查页面的“没找到”，扩大成整个 3.13 文档集合“没有明确规定”。
- 用 configure 的默认支持开关引文同时支持“源码捆绑”，引用与主张范围不完全对应。
- 把默认分配器表格中的配置范围说成 `PYTHONMALLOC` 的全部取值，与已取得图例存在解释不一致。

域名限制不能替代版本选择。一次只限定 `docs.python.org` 的搜索返回了 3.13、3.14 和不同语言的页面，最终仍选出 3.14 memory 链接。

这些结果说明获取能力与证据解释是两个问题。后续有效实验应固定一个错误前的真实输入，单独改变证据供应或范围表达，检查具体主张是否纠正；单纯再次正常结束不足以证明修复。

证据：[历史固定上下文实验](../evals/evidence/2026-09-07-experiments.json)、[真实能力基线](../evals/evidence/2026-09-08-live.json)、[2026-09-10 主张审查](../evals/evidence/review-20260910.md)、[完整研究轨迹](../evals/evidence/boundary-20260910.json)。

## 结构化 think 的作用与引用误填

`think_tool` 是显式研究笔记，不获取新证据。真实调用和结构校验已通过，但尚未证明比自由笔记有普遍收益。

2026-09-10 的对照从同一真实 Session 深复制开始。已有 memory 页 0–24000 字符快照，目标小节在后半段；四次均要求先整理再决定是否续读。首请求仅 think schema 不同，已逐字段断言；按自由、结构化、结构化、自由交错执行，各两次。

四次都识别缺口并续读到 37718 字符。自由模式各用三轮；结构化模式分别五轮和三轮。五轮的那次先把 `snapshot_id` 当作操作引用，再填入工具名 `read_page`，连续两次参数校验失败，最终以空 references 通过。其它组的笔记也存在计数或范围表述不准确，结构合法不认证内容。

允许的结论是：在这个明确要求调用笔记的任务中，没有观察到结构化额外收益，并观察到引用修复成本。该实验未包含无 think 条件，不能据此判断“有笔记”是否比“没有笔记”更有效。

2026-09-12 重放失败前请求：原始组三次中，两次空引用通过、一次错填 snapshot_id，没有正确非空引用；仅在工具正文增加正确调用编号的组三次中，两次正确非空引用，一次缺失 references 字段。两组合法率均为 2/3，不能称为修复，但表明编号呈现可能帮助定位。正确 ID、snapshot_id 和工具名的离线校验行为符合现有规则。尚不能区分协议字段可见性、长上下文定位及随机性。

另将问题改为不强制笔记，比较不注册 think、自由 think、结构化 think，各两次，首请求除工具定义外相同。六次都直接续读后回答，每次两轮，无 think 调用。这个单页续读任务可以不依赖笔记完成；由于可用组也没有实际调用笔记，不能据此得出使用笔记没有收益。复杂多来源任务中的主动使用与实际收益仍待分别验证。

证据：[输入一致性、显式笔记和后续行动](../evals/evidence/think-pair-20260910.json)、[逐组判定](../evals/evidence/review-20260910.md)、[引用定位及自主选择实验](../evals/evidence/think-analysis-20260912.md)。

## Extract 成功不等于目标匹配

在 DeepSeek 文档站点，一个构造的缺失路径返回了 Your First API Call 入门页，服务报告 URL 仍是请求地址，`failed_results` 为空，read_page 判 success。这不同于 example.com 缺失路径报告 404 的正常失败案例；后者曾丢失具体失败原因，已修复并复测。

进一步对照两个不同缺失路径、正常 Vision 页和首页：本机直接 HTTP 访问两个缺失路径均返回 200、无跳转，HTML 哈希与首页相同。两个路径各两次 Tavily basic 提取均返回相同的 4131 字符入门文本。正常页面仍返回图像理解内容。

因此，即使绕过 Tavily，本次访问链路也出现首页回退。无需假设 Extract 凭空替换页面即可解释目标不匹配；尚无服务端日志确定源站、CDN 或代理的内部原因，也不能根据相同哈希证明 provider 缓存机制。

当前成功状态描述“取得非空文本”，不认证文本属于用户预期页面。`partial` 只是本地快照分段，尾段仍为 partial；`next_start=null` 只说明提取快照读完。需要把获取失败、页面回退、提取遗漏、模型误读分别评估。advanced 提取收益尚未实测。

证据：[初次机制样本](../evals/evidence/tavily-mechanism-probe-20260908.json)、[HTTP 与 provider 对照](../evals/evidence/extract-match-20260910.json)、[404 修复复测](../evals/evidence/failure-retest-2026-09-08.json)。

## 搜索数量、域名与结果重复

同题“DeepSeek 官网 视觉模型 图像理解”，每配置各一次：basic 3 条返回一个官方来源；增加到 6 条仍只有一个官方来源；限定官方域名的 3 条全部来自官方站点，但语言版本不是独立证据。advanced 3 条也只取得一个官方来源。修改 chunks 时 URL 也变化，不能单独归因于片段数量。

两次查询的六条结果仅五个不同 URL，同一 URL 可返回不同片段。再次命中不一定无增益，新 URL 也不一定提供新事实。当前精确去重只删除同一次响应中 URL 和正文均相同的条目，不承担跨轮搜索策略。

数量/域名能力可用不代表模型选择最优；标题来自 provider，长标题仍是显示体验的观察项。没有支持自动 advanced、来源数据库或重复查询惩罚的充分证据。

证据：[原始结构取样](../evals/evidence/tavily-structure-sample-20260908.json)、[参数对照](../evals/evidence/tavily-mechanism-probe-20260908.json)、[实际参数使用](../evals/evidence/search-controls-live-20260908.json)、[域名使用](../evals/evidence/search-domain-live-20260908.json)。

## 网页噪声是否需要清理

GitHub releases 页面含 Loading、Uh oh 等提示，源页面与 Tavily 文本均有这些内容，不是本地生成的 API 错误。对查版本修复是噪声，对查页面故障可能是证据，不能全局按 error/404 等词删除。

一次汇总页 Extract 为 51760 字符，具体版本页为 11921 字符，目标更集中但仍含提示。固定问题要求 PowerShell v7.5.10 修复与 PR 编号；原文和仅删除三类完全匹配界面行的副本各测试一次，两者均选出相关修复和 PR #27761，未观察到准确率收益。清理仅减少 227 字符，不能用这两个样本推断通用效果。

优先选择更精确的页面；若反复观察到噪声挤掉目标证据、诱发误读或显著增加上下文成本，再对照清理收益与误删风险。

证据：[抓取及噪声计数](../evals/evidence/tavily-noise-probe-20260908.json)、[内容对照](../evals/evidence/noise-answer-pair-20260908.json)。

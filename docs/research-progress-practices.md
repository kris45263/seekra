# 研究进展与结论一致性：外部实践及 Seekra 适用性

外部资料检索日期：2026-10-04。本文保留当时查阅的机制及迁移判断，外部链接不代表已持续核对。当前实现、后续实验和仍未解决的问题以 [研究进展说明](research-progress.md) 为准。

## 1. 检索结论

能直接借鉴的做法主要涉及：把原始目标与更新状态分开，给完成判断明确的验证依据，保留原资料与恢复边界，以及让评估产生具体可修正的发现。

对“原句已经可见，模型仍把建议写成原文要求”，没有查到可以直接接入并保证解决的通用机制。原句绑定、逐主张核对和独立评估是候选手段，但各自有适用条件。读过证据、引用正确、检查器说通过都不构成语义真实性保证。

下面的“迁移判断”和实验建议是结合 Seekra 记录作出的推断；不是外部作者宣称对 DeepSeek 或 Seekra 已验证有效。

## 2. 官方资料与作者示例实际做了什么

### A. Codex：目标、进展与验证依据分开

[OpenAI 的长期任务案例](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)使用持久的目标、计划与状态材料，以及测试和构建反馈维持工作。其价值在于稳定目标并持续验证；文章明确是实验，不是生产质量保证。

[Using PLANS.md](https://developers.openai.com/cookbook/articles/codex_exec_plans)示例区分进度、发现、决策及结果，并要求记录部分完成和剩余事项。该 recipe 已归档；借鉴组织原则，不沿用其中模型推荐，也不把整套文件模板变成 Seekra 的必需流程。

[Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)围绕结果、验证面、约束、工作边界、迭代方式和受阻条件定义持久目标。这里值得采用的是“完成由什么证明”，不是给 Seekra 增加一个固定循环次数。

**迁移判断：** Seekra 已保留用户原文与可更新状态；还应验证原问题中的各个方面是否得到回答。整体方案已被一个条件否决，不代表用户要求的其他条件都已核实。开放缺口也不自动代表本题无法完成。

### B. Anthropic：增量状态与检查过的结果

[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)使用初始化、功能列表、进展材料和增量工作。条目在测试之后才标为通过，重启时阅读状态并检查环境。该实验主要面向软件开发，不能把可运行测试与自然语言证据解释视为同一种验证。

**迁移判断：** 把“尚未核实”作为默认判断，比让保存成功暗示任务完成更稳妥；但 Seekra 已检查引用与真实交付，也允许未知项。再次增加进度文件或通过状态，不能独自弥补 P1 的语义关系缺口。

### C. 官方演示代码：门禁能约束什么，不能约束什么

[CWC long-running-agents 仓库](https://github.com/anthropics/cwc-long-running-agents)提供证据读取门禁、独立上下文评估和交接材料，声明为未维护的教学示例。不是 Claude Code 的完整内部实现。

具体读过 [verify-gate.sh](https://github.com/anthropics/cwc-long-running-agents/blob/main/claude-code-config/.claude/hooks/verify-gate.sh)：它要求自上次检查以来打开过证据文件，才允许修改结果文件。注释承认可被其他写法绕过、路径比较有限，并且读任一证据会解锁任一结果条目。[evaluator.md](https://github.com/anthropics/cwc-long-running-agents/blob/main/claude-code-config/.claude/agents/evaluator.md)要求读取规范、差异和实际证据后给具体发现；其中 Bash 也不是严格只读安全边界。

**迁移判断：** 可以借鉴“状态改变要有相关证据”的结构，但这份脚本本身不验证对应关系，更不验证语义。Seekra 的范围校验比“打开任意文件”更具体，仍不能证明原句蕴含新增的义务。不能通过再做一层相似门禁宣称 P1 已修好。

### D. 评估者：条件性使用，先校准再信任

[Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)让生成与评估分工，使用明确标准、例子校准及可操作反馈；在软件任务里，评估者还实际使用运行中的应用。作者后来逐项移除框架部件，观察效果，并指出评估的价值取决于任务是否超出当前模型可靠能力。

[Claude Code best practices](https://code.claude.com/docs/en/best-practices)强调提供可验证反馈，也提醒：被要求找问题的评审可能在正确结果中找出问题，追逐每个发现会造成过度设计。

**迁移判断：** 对 Seekra，应先用已确认的正反例检查评审是否能判清对象范围、触发时点和未确认依赖。普通忠实概括、合理推断、明确标注的保守建议不应被误拒。已有自查实验出现漏判与错拿当前状态评价旧记录，不能直接上默认评估者。

### E. 引句与逐主张支撑

[Claude 的 Reduce hallucinations 指南](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)建议允许未知，先取相关原句，再对具体主张寻找支撑；也说明这些办法不消除全部错误。

**迁移判断：** Seekra 已有未知项与短原句。值得试的是逐主张的关系检查：原句的对象、时点和力度是否真的支持这项断言。找到同一个关键词或一条相关引句不算通过。例如“禁止共享访客”支持排除该群体，不能证明“必须是非访客”；提前联网可以作为建议，不能再归为原文提前义务。

该指南也列有请求逐步解释推理的技巧。Seekra 的研究状态应继续保存公开发现和依据；本文没有采用暴露或持久化私有 reasoning 的做法。

### F. 研究 agent：目标、材料整理、报告生成分工

[Anthropic 的 Research 系统经验](https://www.anthropic.com/engineering/multi-agent-research-system)把事实准确、引用契合、需求完整、来源质量和工具效率纳入评价，结合人工观察和轨迹追踪；也介绍外置成果、按引用传回以减少信息在多次转述中失真。其多 agent 结果有特定模型、任务和成本条件。

[Open Deep Research 的作者提示代码](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)分别定义研究目标、资料收集/整理和最终报告模板；整理模板要求保留相关信息。这是提示与分工的源码证据，不能据此证明所有细节在实际运行中都会保留，或引用已被语义验证。

**迁移判断：** 可以在一个现有循环中区分资料支撑与方案表达，不必先引入多 agent。报告应依据原始研究问题和关键支撑句，保留限制与未知。新增定稿阶段是否值得，要用结果和额外成本判断。

### G. 压缩与恢复：保存原记录和近期工作

[Claude Code 工作方式](https://code.claude.com/docs/en/how-claude-code-works)说明工具结果进入下一步决策，以及上下文管理、聚焦压缩和反复压缩无法释放空间时的错误处理。

[Pi 的压缩参考](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)把压缩条目与保留边界持久化，重建摘要加近期消息；不在工具结果处切断调用关系，保留原始条目。其格式包含目标、约束、进度和下一步。

[OpenAI Compaction API](https://developers.openai.com/api/docs/guides/compaction)返回供后续请求直接使用的规范化窗口，其中有不透明压缩项，要求按返回结果续接。该 API 的协议不能直接移植到 DeepSeek。

**迁移判断：** 原记录不等于实际模型输入，交接摘要不等于完整来源，这与 Seekra 当前的记录/投影/快照划分一致。近期结果、目标和阅读入口的保留值得继续验证；所述八次语义生成对照没有发生整理或重建，压缩优化不能解释或单独解决这些样本的 P1 错误。

## 3. 社区提供了哪些反例

以下都是公开用户报告或功能讨论。它们提供场景线索，不证明根因、当前版本发生率或已采纳修复。

| 来源 | 报告/讨论的情况 | 可借鉴到 Seekra 的验证 |
|---|---|---|
| [Codex #35226](https://github.com/openai/codex/issues/35226) | 压缩后重复读文件、重复计划、丢失工作进度；请求保留目标、调查、测试与下一步 | 区分正常回查与无增益循环；恢复后检查实际下一动作及结果 |
| [Codex #42782](https://github.com/openai/codex/issues/42782) | 已完成的计划请求在压缩后重新成为当前行动请求 | 检查当前任务、被核对旧稿和旧状态的时间归属；不能以当前状态否定过去事实 |
| [Codex #30937](https://github.com/openai/codex/issues/30937) | 讨论计划应具有明确语义和生命周期，不能只有计划外观 | 检查计划如何约束实际选择，而不以状态字段齐全作为效果 |

## 4. 候选方向及已有验证

下面是根据外部机制和本地证据提出的方向。来源绑定及其阶段标记已实现；单项正反例、完整回答对照、逐段提取及通用语义指导已做试验，没有证明默认自动审查净收益。提取到了错误主张也可能误判，不能只用提取覆盖来定义修复成功。早期结果见 [2026-10-05 批次汇总](../evals/evidence/research-closeout-20261005.json)，后续结果见研究进展说明。对照应保持非目标变量不变，并记录实际模型和模式；历史实验配置不自动成为新的实现约束。

| 候选 | 对应问题 | 最小动作 | 应验证的结果 |
|---|---|---|---|
| 用户要求的完成依据 | P2、P3 | 把原问中的必要方面与已有回答依据对应；将处理结果未知与尚未调查区别开 | 不遗漏账户/例外；不因延伸未知无限调查；与仅已有进展的对照比较 |
| 逐主张原句对照 | P1 | 对关键“文档要求”逐条取支撑句，比较限定对象、时点、动作和确定程度；建议标出未知依赖 | 能发现对象扩大和新增截止要求，同时允许忠实意译与合理保守建议 |
| 审查对象的来源绑定 | P5 | 已通过 `read_history(view="review")` 关联任务/响应记录、当时进展编号及来源快照；不同类型断言选择不同记录 | 两项新部署核对正确确认旧缺口；仍不能保证语义审查正确 |
| 评估者先校准 | P1、P5 | 小批盲判已确认正反例，先比漏判、误判和新增错误，再试一次反馈修订 | 特别检查“非访客必要”“提前是原文”“立即词不是一律错误”这些边界 |
| 无增益行为信号 | P3、P4 | 使用规范化工具动作、结果/交付范围变化与状态变化记录重复模式 | 提醒变换查询、回查必要依据或带未知回答；不阻止合理重复核对 |

其中，来源绑定能以程序记录提供客观依据；逐主张关系、任务回答是否充分仍依赖语义判断。把建议关联 open 缺口可以帮助发现结构冲突，但关联由模型填写，不能当作对所有隐含依赖的自动识别。

静态判准、来源绑定与关键断言对照已经执行。后续程序枚举全部终稿文本的复核仍未修正目标错误，当前没有把同模型审查接入默认流程的依据。停止与重复行为仍须结合原问题和新证据评估，不能只按调用次数判定。

早期六份结构化答复只在预置完整虚构资料上试验。当前已实现显式 `submit_answer`，支持自由排版、保存原文填充、依赖分类、失败反馈与持久交付；CLI 默认自由回答，受控终稿作为显式可选能力。它保证引用和交付结构，不保证语义或依赖完整性。当前契约见 [显式终稿交付](architecture.md#显式终稿交付)，早期 [结构化样例](../evals/evidence/structured-answer-example-20261005.md) 按其当时配置解释。

## 5. 当前不宜直接复制的部分

- 自动多 agent 或每次回复必经第二模型：官方案例包含独立证据、特定模型和较高成本；Seekra 自查仍有漏判与误判。
- 读取证据后把结论自动认证为真：官方演示门禁自己承认未绑定对应条目，Seekra 的交付范围校验也不验证蕴含关系。
- 每项研究固定若干工具调用、同页重复两次就强制执行：这是任务预算经验或用户建议，不适合原文反复核对，也与不设固定决策上限的当前方向冲突。
- 以更长提示和更多文件代替验证：当前原句可见时仍出错；额外分类指令已有局部而不稳定的效果。
- OpenAI 不透明压缩项、Claude Code 专属 hooks 原样接入：只迁移职责和时机，不假设 DeepSeek 具有相同协议或产品功能。

## 6. 可复用的最小问题材料

后续讨论时先使用这个材料范围，完整日志留在本地证据集，通过来源记录回查；检索没有向外发布 Seekra 日志或发送询问。

1. **目标**：让模型保持规范事实、情境判断和候选建议的对象、时点及未知依赖一致。
2. **现有机制**：稳定原文快照、小节/命中阅读、真实交付范围、局部进展合并、原句与缺口、预算整理及原记录回查。
3. **最清楚的反例**：原文只禁止共享访客，输出却称非访客为必要条件；原句 after 30，建议被归成 before 30 的硬要求；未知重置规则与肯定周期方案并存。
4. **控制事实**：八次生成测试使用正常 120,000 字符预算，没有整理或重建；相关原句仍在最终实际输入中。临时指导只在实验进程生效。
5. **审查反例**：当前核对状态被用于否定旧任务保存事件；旧记录 14 客观保存了该未知项。核对任务不是可靠的自动质量门槛。
6. **成功标准**：真实限定不丢；合理建议不被误拒；未知条件不被暗中当已确定；声明与所引用的证据类型、时间归属匹配。
7. **待选方案**：关键主张对照、依赖关系与审查对象绑定是否有效，增量调用是否值得；尚无直接可保证结果的框架。

本地事实和原始记录的完整索引见 [研究进展说明第 8 节](research-progress.md#8-已暴露问题及原始证据)。外部代码链接多指向可变化的分支，后续实现前应重新核对并固定版本；本文不把当前网页当成永久接口契约。

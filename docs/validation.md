# 验证方法与能力边界

工程正确性与研究答案质量分别判定。运行方式见 [开发指南](development.md)，证据入口见 [实验索引](../evals/README.md)。

## 范围与判定原则

分别评估可确定的 harness 行为和非确定的模型回答质量。工程测试通过、API 正常退出或工具被调用，都不直接等于研究答案正确。

真实用例先确定应检查的事实，再运行；事实依据为对应版本的官方页面，不能将最新版的历史变更标记当成旧版页面已核实。每项标记为正确、部分正确、遗漏、错误或无法核实，不使用一个总分掩盖关键错误。

问题的精确原文和模式保存在 [cases.json](../evals/cases.json)。模型为测试时配置的 DeepSeek，普通与结构化模式使用同一模型；研究模式关闭隐藏 thinking，默认最多 12 次模型调用，Search basic 默认 3 条、可选 1–10 条及域名过滤，Extract basic，页面返回范围 24,000 字符。历史记录按当时配置解释。

## 真实服务用例

|ID|问题目标|检查点|预期和失败判据|
|---|---|---|---|
|simple|只回复你好|工具调用数量|可以直接回答，不应强制搜索/读取/think|
|page|读取 Python 3.13 memory 页面，核对 mimalloc 小节|准确 URL、续读、内容范围、结论|读到目标小节；不能把未记载说成现实中不存在，不能把片段说成全文|
|failure-retest|读取不存在的 example.com 路径，不替换来源|失败原因、是否额外搜索|报告已知失败事实，不编造正文；已知 404 不应丢成泛化失败|
|boundary|普通 GIL 与自由线程构建的捆绑/默认/必需条件|检索进展、版本来源、完整性、停止|区别三个维度，实际来源支持对应版本结论；无法核实时保留未确定项|
|note-free|读取 free-threading 页面后显式整理，再回答|笔记使用与最后结论|默认自由笔记实际执行；未记载与不存在分开|
|note-structured|与 note-free 相同问题|四个字段、操作引用、最终判断|结构合法且引用存在；结构正确不代表笔记内容正确|

`page` 等问题含指定 URL，验证的是读取/使用能力，不验证从零发现 URL 的能力。`boundary` 不提供具体 URL，观察自主发现和选择。笔记用例明确要求 think，只证明调用与格式可用，不证明自主选择或通用收益。

## 执行与记录

1. 独立 Session 运行每个用例，不向模型提供答案检查表。
2. 使用 `scripts/run_live_case.py --case ID --output 新文件.json` 运行。脚本拒绝覆盖已有结果。
3. 记录精确问题、模型、模式、调用次数、耗时、实际答案和操作摘要。当前脚本还保存返回的页面片段和实际搜索参数，机制探查数据可能包含完整提取文本，均属于测试时外部数据而非可信指令。不记录认证头或隐藏 reasoning 字段；发布前检查密钥与无关私人信息。
4. 人工对照官方原文和实际取得的片段/范围判断；正常退出只代表运行完成。脚本不会自动给答案打分。
5. 出现问题时先区分：搜索没取得、harness 处理丢失、读取范围不够、模型误读或来源归因错误。只改变与假设对应的变量。
6. 每个新假设先做小对照；少量重复只用于发现方向，不声称统计显著性或稳定成功率。

官方核对入口：

- [Python 3.13 内存管理](https://docs.python.org/3.13/c-api/memory.html)
- [Python 3.13 自由线程说明](https://docs.python.org/3.13/howto/free-threading-python.html)
- [Python 3.13 构建配置](https://docs.python.org/3.13/using/configure.html)
- [Python 3.13 发布变化](https://docs.python.org/3.13/whatsnew/3.13.html)

## 已验证范围与尚未覆盖项

历史能力证据截至 2026-09-12；下表描述验证范围，不承诺对所有模型、页面或终端均成立。

|能力|现有证据|限制|
|---|---|---|
|安装与配置|独立目录帮助、版本、模块入口、UTF-8、本地 REPL 命令工程验证；真实连续问答子进程退出码 0|默认配置来自启动目录，移动可编辑安装后需重新绑定|
|流式显示|增量 flush、正文不重复、普通/verbose 请求一致、诊断故障隔离|已显示正文不能撤回，stdout 可能含中间说明或失败残稿|
|生成中取消|实际 PTY 发送 Ctrl+C 后恢复输入并保留原暗号|一次有效样本；未实测工具 HTTP 阻塞阶段、物理键盘差异及套接字释放时间|
|页面获取|指定 URL、同快照续读和 404 错误反馈有真实记录|提取快照读完不等于网页完整；success 不认证目标匹配|
|数量与域名|真实请求已使用 max_results 和 include_domains|不保证版本选择、独立来源数量或模型策略最优|
|think|自由/结构化真实调用；同输入格式对照|未证明通用收益或相对无 think 收益；有引用误填反例|
|事实判断|版本问题有实际来源与最终答案可逐项核对|仍有否定范围扩大、来源归因不准确，不能认定复杂题已解决|

具体判定见 [研究发现](research-findings.md)、[2026-09-10 实验报告](../evals/evidence/review-20260910.md) 和 [2026-09-12 笔记实验](../evals/evidence/think-analysis-20260912.md)。

## 复现实验的解释范围

指定 URL 的用例检验读取与使用，不证明自主发现来源。要求先调用 think 的实验检验显式整理，不证明自主选择笔记的收益。复杂题应逐项核对主张与实际收到的页面版本、文本和范围；“没有取得支持”不能改写成“现实中不存在”。

固定上下文对照需要保存共同输入、唯一变化项和差异断言。只修改一个待检验因素；后续轨迹允许自然分叉。少量重复可以发现机制线索，不能得出稳定成功率或统计显著性。历史网页和模型服务不可完全复现，已有 JSON 的 judgment 可能是待核对占位值，人工结论以对应实验报告为准。

## 持久会话与上下文验收

工程回归包括磁盘保存/重载、失败续接不重复搜索、持久页面快照续读、未知工具结果阻止恢复、配置变化拒绝续接、尾部残片恢复、文件锁、上下文回读以及 provider usage。`test_runtime_edges.py` 还覆盖整任务裁剪、当前任务超限暂停、reset 前记录的读取隔离、失败/取消记录的状态标注、展示回调与正文输出故障的区别，以及存储失败保留原始异常。所有这些工程用例使用临时目录和假服务。

跨进程会话恢复可用两个独立进程完成同会话追问来验证；用量显示可对照原始 usage 与终端累计。取消验证区分模型生成中 Ctrl+C、程序化令牌取消及工具 HTTP 阻塞三类；模拟响应关闭不等于所有网络状态均能立即停止。日志恢复通过也不等于模型在长历史中能稳定选中正确记录。这些方法按本次改动涉及的行为选用。

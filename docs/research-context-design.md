# 研究资料与上下文重构设计

状态：部分实现。来源关联、稳定快照、目录、小节读取、关键词查找、本地续读、精确引用核对、研究进展、有效进展检查点、整批结果展示预算及轻量历史视图已接入执行循环。Search 已支持每来源片段数；跨轮同来源的完全相同片段已压缩展示。不同 URL 或非完全相同内容的重复判断、按问题 Extract 摘录接入和参数默认策略仍需后续判断。本文面向 Seekra 开发者，说明目标职责、接口语义和验收要求；具体实现与证据边界以对应代码、测试和实测记录核对。

## 1. 目标与整体流程

搜索能力用于发现来源和定位信息缺口。模型根据用户要求与已有证据判断还缺什么，再通过搜索发现相关来源、取得线索，通过正文阅读核实具体问题。研究过程中形成的发现及其出处应能持续使用，即使早期正文已经退出模型上下文。

本轮重构继续使用 Tavily 提供网络搜索与页面提取。实现采用普通 Python 和现有单一执行循环，围绕以下流程组织：

```text
用户要求 + 最新研究进展
          ↓
模型判断信息缺口
          ↓
搜索发现来源 / 在已有资料中查找 / 读取明确页面
          ↓
保存资料快照，返回相关正文及位置
          ↓
模型更新发现、适用条件、出处与未解决问题
          ↓
按预算选择下一轮上下文
          ↓
继续研究，或核对覆盖情况后回答
```

这不是每个问题都必须经过的固定步骤。简单问题可以直接回答；已有 URL 可以直接读取；已有快照可以在本地定位。复杂任务才需要多次更新进展和整理上下文。

本设计有三个交付目标：正文可以直接定位与回查；长任务的进展可以保存和恢复；Tavily 的结果控制能力能够在这套流程中被有效使用。参数选择和答案质量收益通过实验判断。

### 1.1 决策依据与效果原则

模型应根据用户目标和当前实际可见的信息决定下一步。harness 负责提供来源明确、范围可知、可继续使用的线索，不能要求模型猜测未展示页面的内容或位置。设计目标是让决策有依据并推动任务；程序负责保证资料传递、标注与定位符合接口契约，来源是否可靠、模型是否选择恰当、操作是否有效，需要通过原文核对和真实任务验证。

1. **先提供选择依据，再让模型选择。** 搜索结果需要相关片段帮助选择来源；长页面需要实际结构或查找结果帮助选择位置；正文与适用条件支持结论。资料编号只负责定位，不能替代这些信息。
2. **区分取得、交付与理解。** harness 保存了资料，不代表资料进入了本轮模型请求；内容进入请求，也不证明模型正确使用了它。分别记录取得的资料和实际交付内容，通过模型后续调用和回答判断使用效果。
3. **把内容来源与选择方式说清楚。** Tavily 根据查询选择搜索片段；harness 从实际提取文本解析标题和小节边界，根据命中或读取目标生成阅读视图；模型选择来源、小节、查找词和下一步操作。小节名称沿用提取文本中的原文，harness 不自行命名或补全结构，也不把开头窗口称为与问题最相关的段落。
4. **让范围限制与下一步操作可见。** 部分目录、部分正文、未命中、提取失败和未取得全文需要明确区分，并提供适用的继续方式。模型主要选择阅读对象，harness 负责边界与单次返回大小；续读游标只指向后续未展示内容，不表示那里存在答案。普通分页不必等到整次请求接近 `context_limit` 才发生。
5. **整理与去重后仍保留可用线索。** 被外置或合并的资料要有标题、内容类型、必要的短预览与回查入口。不能因为曾经返回过，就假定模型后续仍知道其中内容。
6. **依据、理由和效果分别检验。** 工具选择可以基于待验证的假设；没有新增事实也可能帮助缩小范围或发现冲突。通过可见上下文、调用参数及结果检查这种联系，不要求每次调用额外写一段理由，也不把模型事后解释当作效果证据。研究进展只需记录影响后续工作的简短判断、缺口与下一步，不记录隐藏思考。

|模型要作出的选择|harness 应提供的依据|该依据不能证明什么|
|---|---|---|
|选择来源，或改写查询|用户问题、已有缺口；各候选的标题、URL、相关片段与获取状态|有 URL 不代表已取得正文；片段相关不代表足以支持结论|
|选择页面中的内容|实际小节标题、标题路径、长度与稳定引用；字面命中及附近正文；已展示范围与续读入口|标题不证明小节内容正确；下一段位置不证明那里有目标事实|
|形成发现，或继续查证|实际正文、来源类型、版本线索、范围限制及已有冲突|工具成功、读完快照不证明网页完整或结论真实|
|恢复早期工作，或结束任务|最新进展、未解决项、可发现的历史资料及精确回查入口|状态已保存不证明事实齐全；调用预算耗尽不代表任务完成|

## 2. 起点问题与设计依据

重构前，`retrieval.py` 只在单次搜索内按完整 URL 与片段精确去重；`Session.read_record` 将整个执行事件序列化后按字符切片；`context.build_context` 根据长度和消息顺序外置工具结果，并豁免全部历史读取结果。当时已有页面快照和研究笔记，但缺少面向正文的统一定位接口，以及上下文整理后持续保留的当前研究进展。这些起点问题解释后文的设计理由，当前实现见 [架构说明](architecture.md)。

两份现有记录说明了重构需要解决的具体失败：

- [历史回读实验](../evals/evidence/context-history-20260927.json)：连续回读可能使下一次模型请求超限；只允许旧回读退出的候选策略，又出现读取过八章却只回答后三章的情况。
- [上下文预算与工具交付对照](../evals/evidence/context-budget-comparison-20260927.json)：某次搜索的重复正文占完整返回约 23.1%，选定的可精简字段只占约 2.3%；固定历史节点中，较大预算保留了影响答案的条件。自主运行的小样本结果各有局限，不能据此确定最优预算或稳定成功率。

这些证据支持分别处理重复、定位、进展保留与预算，不能把减少字符数本身当作研究能力改善。

参考实践及采用范围：

|实践|用于本设计的机制|在 Seekra 中需要验证的部分|
|---|---|---|
|[Anthropic 上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)|保留轻量引用，按需读取；用持久笔记维护长任务|模型能否选中正确资料，并在移出正文后继续完成目标|
|[Manus 外部记忆](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)|外置内容保留恢复入口，维护当前任务进度|资料可恢复之外，模型是否知道何时、去哪里恢复|
|[Deep Agents 上下文管理](https://www.langchain.com/blog/context-management-for-deepagents)|外置大结果，保留进展与原始记录；主动触发整理检验恢复能力|整理后的条件保留、事实回查与目标连续性|

借鉴的是这些机制及其验证方法。具体数据结构、工具接口与阈值按 Seekra 的实际任务设计。

## 3. 数据归属与模块职责

### 3.1 数据与阅读视图

|对象|内容与用途|产生、保存与消费|
|---|---|---|
|来源 `Source`|关联同一目标页面地址的搜索片段、页面提取和相关摘录；帮助识别内容之间的关系|程序根据实际 URL 和获取记录建立关联；模型看到来源编号与各次获取结果|
|资料快照 `Document`|一次取得并保存的文本及来源，用于原文查证|检索模块取得；Session 保存对应执行事实；资料模块建立索引并提供读取|
|小节 `Section`|从一份页面快照解析出的原文标题、层级与范围，用于按节阅读|资料模块解析；小节引用固定到该快照和对应解析规则，不另存一份改写正文|
|研究进展 `ResearchState`|当前任务的发现、条件、引用与缺口，用于延续研究|模型提出更新；程序校验并记录；上下文模块选择最新有效版本|
|本轮上下文|本次请求实际携带的目标、进展、历史与正文|上下文模块生成；模型消费；原始执行记录不因外置而改变|
|本轮交付记录|记录最终请求选用了哪些消息、进展版本、页面概览和正文范围，用于复核决策依据|上下文选择完成后记录；检查模型行为时与对应调用、回答一起核对|

Session 的执行记录仍是恢复依据。来源、资料与小节索引，以及最新研究进展，都是可重建的视图，不各自维护一份与记录独立变化的事实来源。执行状态中的 `running`、`paused`、`completed` 等与研究进展中的“哪些问题已解决”分别表达运行情况和模型判断。

### 3.2 模块落点

|模块|重构中的职责|
|---|---|
|`retrieval.py`|调用 Tavily、校验响应、区分搜索片段与提取文本；不替模型判断研究结论|
|拟新增的 `documents.py`|从已提交记录建立来源与资料索引，解析实际小节边界，管理稳定引用，提供目录、查找、小节读取与窗口分页；本地回查不发网络请求|
|`session.py`|提交与恢复资料、进展及运行事实，执行 reset 隔离；索引可随记录增量更新|
|`tools.py`|定义模型可用操作、校验参数、返回有界结果；明确哪些操作联网、哪些只读已有资料|
|`context.py`|计算预算，选择进展和正文，生成可回查引用与实际交付记录；不在投影函数中调用模型生成摘要|
|`agent.py`|安排常规决策及必要的进展整理，将所有模型调用纳入现有预算、取消、用量与恢复流程|

工具的完整获取结果与交付给模型的阅读视图需要分开。日志保留诊断参数；阅读视图保留来源、内容类型、状态、引用和正文位置，避免把整份日志再交给模型。

模型通过工具调用与 harness 沟通。每次模型请求提供工具说明及参数约束；模型返回结构化调用，harness 执行后把阅读视图作为工具消息加入后续请求。工具说明和返回值共同解释如何选择来源、小节或查找命中，以及如何复制引用和游标继续读取。普通文字中的“继续读”不是执行指令，程序也不要求模型预先猜出正文位置或阅读长度。

## 4. 资料引用与正文接口

### 4.1 来源、获取结果与阅读窗口

来源对应一个已知的目标页面地址，不等于整个网站。同一来源可以被多次查询发现，也可以多次提取。每次获取保留其查询或读取操作、时间、实际地址和结果，便于判断版本差异、来源冲突和资料是否重复。

每份资料快照至少包含 `source_id`、`document_id`、`content_kind`、标题、请求 URL、服务报告 URL、取得时间、正文，以及所属任务和执行记录引用。未取得的元数据保持缺失。地址不一致时分别展示请求地址与报告地址；不能仅因标题或域名相同就合并来源，也不能把报告地址自动称为最终重定向地址。

`content_kind` 区分搜索片段 `search_snippet`、按查询取得的相关摘录 `query_excerpt`、页面提取文本 `page_text`。模型笔记不登记为外部来源。`page_text` 只表示保存了本次提取结果，不保证覆盖网站全部内容。

对模型的引用展示应体现来源关系，例如：

```text
S1：同一个目标页面地址
├─ S1-R1：某次查询取得的搜索片段
├─ S1-R2：另一次查询取得的搜索片段
├─ S1-E1：按具体问题取得的相关摘录
└─ S1-P1：一次页面提取快照
   ├─ S1-P1-H1：Overview
   ├─ S1-P1-H2：Supported platforms
   ├─ S1-P1-H3：Requirements
   └─ S1-P1-H4：Limitations
```

这里的 `S`、`R`、`E`、`P`、`H` 展示形式用于说明来源、获取结果与小节的关系，具体编码在第一阶段定稿。工具同时返回明确的类型与关联字段，模型直接复制引用，不需要拆解编号。按来源分组展示不要求底层是一棵严格的树：多次查询可发现同一来源，获取记录仍保留与各次查询的关联。

第一阶段的搜索只保存实际返回的片段，不预先提取每个候选 URL。模型选中来源后，通过 `read_page` 提取已知 URL；这一步是读取页面，不是根据搜索标题再次发起搜索。搜索片段可能由几个不连续的摘录组成，其位置只属于片段文本，不能推算完整页面的位置。

一次新的网络获取保留自己的获取记录与资料引用，旧引用继续指向当时的文本。阅读窗口则是同一快照的一段：读取 `S1-P1` 的开头、某个小节或后续窗口，都不会生成另一份来源或页面快照。正文保存一次；目录、小节和窗口以范围引用它，第一版不预先把整页切成独立保存的小块。

第一阶段从既有 `tool_completed` 记录投影资料：搜索结果登记各自的片段，`page_updates` 登记实际取得的页面快照；续读、目录查询和历史回读不重复登记同一正文。引用与已提交的记录身份稳定关联，重载后可重新定位。解析旧结果时只接受已识别的结构，不执行其中的指令或推断缺失字段。

### 4.2 规范文本与小节边界

正文先统一换行并完成必要的密钥遮蔽，再建立位置和内容标识。持久保存、当前读取和重载读取使用同一份文本，避免当前 `Session.record` 中内存文本与磁盘遮蔽文本可能不同而导致位置漂移。快照建立后，不再按不同读者重新清理、摘要或重排。

底层范围统一使用 Python 字符串的零起点、左闭右开区间 `[start, end)`，不计 JSON 转义、事件字段或展示标签，也不是字节或 token 偏移。范围用于内部读取、精确引用和必要的局部回查；模型通常选择工具给出的阅读对象与游标，无需自己计算偏移或填写试探性的长度。

网页作者编写原始内容与标题；Tavily 提取后返回 Markdown，未必完整保留网页结构；harness 只解析实际保存的提取文本。首版使用确定的 Markdown 标题解析规则，并按以下方式建立小节：

- 小节从已识别标题开始，结束于下一个同级或更高级标题之前；最后一节结束于快照末尾。上级小节包含其下级小节。
- 小节名称沿用标题原文，层级来自标题标记；harness 不改写、翻译、命名普通段落或调用模型补全目录。代码块中的伪标题排除。
- 每个小节有固定到快照的小节引用、标题路径、层级、精确范围和长度，以及最多 180 字符的原文预览与对应范围。同名小节用路径、预览和唯一引用区分，模型不按标题字符串猜测目标。
- 标题之前的导言仍能通过普通正文读取访问，不因没有所属小节而丢弃。没有可靠标题结构时明确标记未识别到目录，不编造小节。

小节边界表达的是提取文本结构，不代表语义上独立或事实齐全。条件可能位于上级导言或其他小节；工具保留标题路径和实际交叉引用，模型可据此查看上级内容或相关部分。

旧记录以已经保存的文本为回查依据；若只有片段，只登记实际保存的内容并注明类型，不重新抓取网页冒充旧正文。补取产生新引用。小节引用的恢复还需要固定解析规则版本与编号映射，不能在升级解析器后把旧引用指向不同范围。

### 4.3 面向模型的操作契约

以下工具名为拟定名称。模型主要选择来源、小节、查找命中和继续阅读，程序负责精确定位与分页。工具说明明确联网、读取已有资料和精确范围回查之间的区别。

|操作|输入|返回与行为|
|---|---|---|
|`list_documents`|分页游标；可选任务或来源范围|按来源关联的有界资料目录，包含资料引用、标题、URL、类型、长度、时间、任务状态和短预览；保留不同查询与获取记录|
|`read_page`|明确的 URL，以及对应的获取参数|调用 Tavily，保存新提取结果，返回与来源关联的快照编号、页面概览和首个正文窗口；后续本地读取不再次提取|
|`read_section`|`section_ref`；可选续读游标|读取该快照中的指定小节；单次预算内可完整返回时返回整节，否则返回部分并附小节续读游标；不要求模型填写长度|
|`find_in_documents`|非空查找文本；可选资料编号；分页游标|字面查找并返回命中引用、位置、附近正文及所属小节引用（若有）；标明查找范围与后续游标|
|`read_document`|阅读对象引用；可选游标或精确范围；页面目录模式使用目录游标|按资料编号顺序读正文，或按命中引用展开附近内容；页面目录模式返回小节目录。窗口大小由程序控制；精确范围是补充入口，不作为默认阅读方式|

`find_in_documents` 第一版采用精确匹配，不引入语义排序或正则表达式。命中引用固定到快照及实际位置，不能因另一次查找而改变指向。返回命中附近的原文，合并重叠展示窗口时仍保留各命中位置。有可靠小节时，模型可以用返回的 `section_ref` 阅读整节；无小节时，`read_document` 从命中附近的自然段展开，提供向前或向后继续的入口，不要求模型猜字符数。

查找结果说明查了哪些资料、使用什么词、是否完成以及是否还有未展示命中。未命中只说明已查文本没有对应字符串；模型可以根据原文语言换词、查看小节目录或顺序阅读。当前只有搜索片段时，也可以请求提取页面。查找未完成时需另标明剩余范围，不能把这些结果扩大为“页面未讨论”或“现实中不存在”。

分页游标固定到资料集合、快照、阅读目标、方向与进度；新资料加入或页面刷新不会改变旧游标的指向。资料目录、页面目录、查找结果、小节续读和正文续读使用对应工具与模式，工具返回值明确说明入口。无效、过界、用于其他目标或 reset 前的引用和游标均返回明确失败，不自动改读最新页面。重载后仍能使用尚可访问的引用和游标。

资料操作只访问当前 Session 允许读取的数据，不接受任意本地路径；资料缺失不自动联网。失败或取消任务中实际取得的内容仍可回查，并附原任务问题与状态。`list_history`、`read_history` 保留原始问答、执行经过与旧接口用途；新正文外置使用资料引用，不重解释旧 `read_history(record_id, start)` 的事件 JSON 偏移。

### 4.4 首次读页与按节阅读

长页面首次返回应帮助模型选择内容。`read_page` 保存文本后，提供以下信息：

- **来源与快照信息**：来源编号、快照引用、标题、URL、类型、取得时间、总长度和提取覆盖限制。
- **实际小节目录**：原文标题、标题路径、层级、小节引用与长度。精确位置供核对和内部读取，模型可直接选择小节引用。
- **开头窗口**：明确标记为开头正文，附实际范围与正文续读入口；它不是相关性排序结果，不保证包含目标事实。
- **目录状态**：是否识别到结构、当前目录是否完整；目录超出预算时给独立的目录游标，不能把未展示小节当作不存在。标题笼统时，模型可先读取该节或查找关键词，不把标题当作正文结论。

模型选择一个小节后，harness 根据已解析的边界与单次返回预算处理：整节能放入时完整返回；放不下时从当前进度返回一部分，优先在自然段或完整文本块的边界结束。单个自然段、表格或代码块本身超过预算时，可以按字符分段，但明确标记文本块仍有后续；每次续读有进展、不跳过正文，不跨入目标小节之外。读取上级小节时，其下级内容属于目标范围。

每次结果包含目标小节引用、完整目标范围、本次返回范围、正文和下一段游标。完整性描述针对本次结果：只有本次包含整节才能标为完整；最后一页仅表示到达小节末尾，不能声称此前各页仍在上下文中或已被模型理解。实际展示过的范围由交付记录核对。

单次返回预算用于正常分页，和整次模型请求的 `context_limit` 分开，见第 6.3 节。harness 可以按剩余交付空间缩小窗口；若连最小可用窗口及元数据都无法容纳，应先整理上下文或按预算不足停止，不能反复返回空正文和不前进的游标。

例如，用户核实软件 X 的启用条件，`S1-R1` 的搜索片段提到 `Requirements`。模型调用 `read_page` 读取该 URL，得到 `S1-P1` 的页面概览及 `S1-P1-H3` 小节引用；随后调用 `read_section(section_ref="S1-P1-H3")`。若结果标记仍有后续，模型可复制游标继续读取同一节。读到“其他限制见 Limitations”时，再从目录或查找结果选择对应小节。以上编号和名称仅为示意；小节范围与每次返回长度由 harness 根据实际文本和预算确定。

这条交互中，搜索片段支持选来源，目录和命中内容支持选阅读对象，实际正文支持判断条件及缺口。若没有可靠目录，模型仍能使用查找和普通正文续读；若两个来源冲突，可按来源、版本与具体原文核对。选中一节不等于答案已充分，需要结合用户问题判断还应查什么。

### 4.5 重复内容的处理

重复处理发生在保存关系和阅读交付之间。相同正文再次出现时，可以返回已有正文引用和新的来源关系，减少重复展开；保留标题、类型及短预览，使它在早期正文退出上下文后仍能被识别和选择。不同查询取得了新片段时应展示新线索，不能只因 URL 已出现就省略。正文必须仍可主动读取，已交付过不等于模型现在仍能使用。

第一阶段只处理可明确确认的重复：同一页面地址与相同正文；对于仅 fragment 不同且正文相同的结果，可以共用正文展示，同时保留全部原 URL。查询参数、版本路径和不同正文不据此合并。不同来源的相同文本保留各自来源，不把文本相同当作独立证据数量相同或来源等价。

## 5. 研究进展的更新与恢复

研究进展是当前任务的可更新成果记录，由 `update_research` 提交。原始用户要求由程序保留；模型对目标的概括不能覆盖用户原文。当前保存的内容如下：

|内容|用途|
|---|---|
|目标与约束的理解|提醒模型回答范围、版本与来源要求|
|发现列表|每项有稳定 `id`，包括 `summary`、`conditions`、`status` 与 `references`，可附关键原句 `evidence_quotes` 和关联缺口 `gap_ids`；状态 `supported`、`uncertain`、`conflicting` 都是模型判断，不是程序认证|
|缺口列表|每项有稳定 `id`、待核实问题、`open/resolved/dismissed` 状态和处理说明，可带 `answer_impact` 说明对原问题的作用；事实缺口解决需要正文引用|
|阅读目标|保存实际小节、资料、引用、明确 URL 或查找词，必要时保存对应续读游标和 `gap_ids`；程序据此生成来源关系和阅读动作|
|下一步|准备核实什么，以及预期如何改变原问题的回答；改变方向时由模型同步更新，省略保留旧计划，空文本清除|

读取工具为实际返回的正文附上可直接复制的 `evidence_ref`，例如 `S1-P1@820-1040`。模型把该编号放入发现的 `references`，程序解析、校验后保存 `{source_id: "S1", document_id: "S1-P1", start: 820, end: 1040}`；也兼容直接提交这一对象。查找结果的 `match_range` 与 `match_ref` 只定位关键词，`start/end` 和 `evidence_ref` 覆盖返回的附近正文。标题和目录支持选择阅读对象，但不能代替具体正文支持事实结论；未交付部分仍是待核实内容。小节只读了一部分时，引用只覆盖实际取得依据的范围，不能用整节引用暗示已核实未读部分。引用有效只证明定位关系，是否支持发现仍需原文对照。

模型可主动调用 `update_research` 保存需要持续保留的成果；接近上下文预算时，harness 也会安排第 6.2 节的临时进展保存阶段。默认研究流程已统一使用这个工具，旧笔记不再出现在默认工具集合中。历史笔记仍可查看，旧实验保留显式 Python 入口。

更新带上 `base_revision` 和 `operations`；未保存时版本为 0。模型只提交新增、修订、解决、重新打开或移除的条目，程序保留未修改内容并分配稳定编号。可选更新 `goal/next_step`，空操作确认已有状态。程序校验版本、大小、字段、资料可见性和引用范围。每版状态最多 8,000 个序列化字符，最多 20 项发现、20 项缺口和 10 个阅读目标，每项发现需要 1–8 个正文引用。没有依据的假设放入缺口；只有目录时可保存阅读目标，无需借用其他正文引用。工具返回候选结果后，通过现有 `tool_completed` 记录完成提交，再替换当前视图。任何操作失败或存储失败都不发布半批结果；每次成功更新保留历史版本，恢复时从已提交记录重建。

可引用范围根据 `context_selected` 的实际消息选择和替换内容重建，并在对应请求取得完整模型响应后计入。目录预览、已经外置的正文和只保存但未交付的范围不据此成为已读证据；请求发起后失败也不单独构成交付确认。相邻已交付范围可以合并，有缺口的范围不能合并成连续证据。这证明客户端交付范围，不证明模型理解或引用支持结论。

重要发现可以选取最多三条、每条不超过 400 字符的原句。程序限定在这条发现的引用范围内，先做字面匹配，再处理明确的内联 Markdown 链接、转义与空白差异，并保存实际原文和精确坐标。格式等价选取存在多个位置时不猜测，要求缩小引用或补足文字；不接受改写、翻译或在引用范围外寻找文字。实际请求中的这些已定位原句属于来源摘录，参与当前可见范围计算；原句不替代上下文和语义核对。

可选 `gap_ids` 明确某项发现或阅读目标用于调查哪些已有缺口，程序生成 `gap_links`。删除缺口前需显式修订关联，关联不自动解决问题，也不自动移除目标。模型状态的 8,000 字符限制包括关联与原句，`state_budget` 返回实际大小和剩余量；程序生成的视图另外计入请求预算。

缺口的 `answer_impact` 也是模型维护的文本，计入上述状态预算，新增与修订均可省略；省略保留旧值，空文本清除旧说明。它让后续决策能区分会影响用户答案的缺口与延伸问题，不自动改变缺口状态或限制工具调用。模型指令要求在继续研究前判断信息对原问题的作用，并在回答及建议中保留证据的条件、例外和确定程度。已有充分依据或剩余事项能明确说明无法核实时，可以保留 `open` 缺口后回答；用户明确要求调查的事项仍须处理或说明无法核实。保存有效和原句匹配都不能证明这种判断正确。

阅读目标的程序导航提供原始标题、来源和快照编号、实际范围与 `read_action`。`ever_delivered` 表示历史累计交付，`current_input` 根据本次最终消息选择计算，取值 `none/part/full`。程序能证明未修改条目继续保留及入口有效，不能保证模型选对目标、写全条件或整理后继续完成研究。测试需分别核对保存内容、实际下一次输入和模型行为，引用有效或更新成功不能替代语义验证。

顺序正文、小节和引用目标可通过 `first_undelivered` 找到累计交付范围中的最早缺口及续读动作。入口固定到保存的快照和目标边界，不能由模型目的文本推断位置，也不能从晚处已读片段推断中间内容已读。它是供模型选择的导航，不把全文交付当作任务完成条件。

正在引用或选择的资料另有 `document_coverage`。即使阅读目标已移除，仍被发现或缺口引用的资料也保留累计交付与当前可见概况。每份快照单独计算，不把同源片段合成整页。概况最多展示八份资料和每份前三段累计范围，省略的资料编号与范围数量明确列出；完整覆盖判断使用全部实际交付范围。当前不可见不等于从未交付，累计 `full` 也不等于用户问题已全部核实。

研究进展按用户输入形成的任务归属。恢复同一未完成任务时使用其最新版本；新问题从版本 0 开始，旧任务进展作为历史工具结果保留，并可通过历史工具回读，不成为新任务的当前进展。reset 同时隔离正文索引和进展；磁盘上的旧记录保留现有规则。

## 6. 上下文选择与预算

### 6.1 每次请求需要保留什么

下一次请求由原始用户要求、相关历史前提、最新研究进展、近期完整工具交互和当前需要的证据构成。最新进展在请求中作为标明“模型生成的工作记录”的数据展示，不作为更高优先级的指令。完整资料目录通过工具取得，不无界地注入每次请求。

模型在最终回答前按用户要求检查覆盖情况，必要时回查条件、否定、版本和冲突。这个要求首先通过模型指令和评估实现；程序不能仅凭发现列表非空就判定答案已经正确或完整。

完成本轮上下文选择后，记录最终请求实际采用的消息或交互组、进展版本、来源与快照关联、小节或命中引用、实际正文范围、完整性标记及页面概览。原工具结果已经持久保存的文字可以按记录引用；上下文模块新生成或裁剪的预览、目录与提示，应保存实际呈现内容或可无歧义复现它的选择记录，不能只保存目标小节编号和字符总数。再次裁剪时同步修正正文引用、覆盖标记与继续入口，不能仍声称交付了完整小节。保留渲染规则版本，防止后来修改格式后无法复核旧请求。

交付记录对应本轮最终请求，而非投影前的工具输出；同时关联模型请求是否实际发起及其结果。它证明客户端送入了什么信息，不证明服务内部如何处理，更不证明模型理解了什么。没有这些信息的旧会话保留“无法确认当时交付范围”的证据边界。

### 6.2 何时整理，怎样继续

当前实现以硬字符上限的 80% 作为提前整理阈值。该值用于给进展更新和后续结果留出空间，是实现起点，尚未充分调优。执行记录保持追加保存，活动上下文可以依据已经成功提交的进展形成检查点。

普通小节分页按单次阅读预算工作，即使上下文很空也可能分成多页。当前任务的整理则取决于整个请求的消息与工具定义长度。单条工具满足窗口上限，不保证多个新结果同时放得下；旧正文外置和任务裁剪后仍超限时，整批分配模块按共同正文上限压缩最新完整结果组，更新实际引用与继续入口。未展示的匹配、资料或目录条目明确标记，必要导航仍放不下时暂停。

触及软阈值后，执行循环按以下顺序处理：

1. 先沿用正文外置和旧任务裁剪规则，并持续应用之前已经提交的检查点。
2. 如果接近阈值，尝试用最新有效进展推进检查点。保留原始问题、保存这份进展的整组工具调用和之后的完整轮次，移出此前的当前任务决策消息。同一批中与进展并行取得的结果仍保留，不认为这些结果已经由该进展覆盖。
3. 如果仍接近阈值且不是刚保存进展，进入临时整理阶段，先保存已知发现、条件、例外、引用、未核实事项及下一步。模型可用 `read_document` 核对已交付的引用范围，或从已有引用展开附近正文以纠错；普通搜索和新资料阅读暂时停用。任务没有完成也可保存，暂时没有发现时列表可以为空。信息足够时也可直接回答。
4. 阶段在本次 `model_started` 落盘时发布，可见工具和实际执行同时遵守边界。更新失败保留原有效版本与旧轮次；更新成功落盘后，下一次请求形成新检查点并恢复普通工具。同一批响应中与更新并列的调用仍遵守原阶段。更新和回查计入正常调用、用量和耗时；范围校验不认证进展语义，也不能把后台已保存但尚未读取的文字算成依据。
5. 普通工具定义下不能构造请求时，有可保存的阶段内容且提供进展工具，则尝试使用整理阶段的较小工具集合。必要内容仍无法容纳时暂停；原始问题、最新有效进展和刚取得的资料不静默截断。阶段不会因为工具集合变小而自行退出，必须成功保存进展，或由模型直接回答结束任务。

`context_selected` 保存阶段、实际工具定义、检查点的进展记录编号、移出消息数量、整理请求标记、阈值、实际消息索引和替换值。重载后可恢复相同选择，并复核实际发送内容；记录本身仍保存全部原过程。

整理阶段的阅读动作按当前权限呈现。普通续读入口保留原参数和游标，但标为 `availability=after_progress`；可用于局部回查的引用动作标为 `local_reference`，具体范围仍由执行端验证。外置资料提示及系统补充的回查说明也按阶段权限生成，避免提示调用当前停用的普通工具。阶段参数结构区分 `reference` 续读与 `text` 周边展开，后者不接受普通页面游标。保存成功后恢复普通工具并移除临时动作标记；原始获取记录不改写。正文裁剪、进展导航与重载资料中的动作使用同一规则，实际标记内容计入请求预算。

参数有效的普通本地阅读被阶段限制时，返回 `progress_required` 与保留原参数的 `deferred_action`；参数核对不会交付正文。非法参数和引用仍按具体错误纠正。待执行入口可以进入保存的阅读目标，也在恢复资料中保留；阶段退出后由模型重新选择，不自动重跑。

资料回读与网络读取都使用稳定快照和正文引用。回读结果可在后续整理时退出；正文引用直接回到原快照，小节引用和游标也固定到该快照，不形成回读引用链。`read_history` 默认提供原始消息、失败原因和资料导航，原小节、引用与命中入口保留；原事件 JSON 通过显式 `raw` 视图读取，两类偏移不混用。历史读取仍保留原有正文外置豁免；较早交互可以随有效检查点整组移出。

研究进展本身也有预算。超限时要求模型整理或分出可回查的历史发现，保留当前覆盖概况与引用；不能无界增长或由程序按字符截断。具体策略需用长任务验证，保证处理正文积累的同时没有把同一问题转移到笔记中。

### 6.3 预算单位和取值

三种预算分别约束不同范围：

|预算|约束对象|影响的行为|
|---|---|---|
|单次工具返回预算|一次正文、目录或小节阅读结果，包含必要元数据|决定整节返回还是分页；平时也生效，由程序选择窗口大小|
|整批工具交付预算|同一轮模型响应产生的全部工具结果|分配每个结果的展示空间，必要时缩小窗口，保留各自范围和继续入口|
|整次请求上下文预算|本次模型请求中的指令、用户问题、历史、进展、工具定义与工具结果|软阈值触发整理；硬上限阻止超限请求发出|

现有 `max_context_chars=120000` 属于整次请求的序列化字符保护值。第一阶段保留其单位和接口含义，同时设置单次与整批交付的有界策略。小节分页可以在上下文很空时发生；剩余上下文较少时，同一小节也可能分成更多页。分页始终固定到同一快照和目标范围，不能因每页预算变化造成跳读、重复推进或跨节。

第二阶段引入上下文整理的软阈值和预留量，再根据模型的可靠 token 计数能力校准；没有匹配计数器时明确标为估算，并保留保守余量。已有 usage 只描述过去请求，不能直接代表下一次请求大小。序列化字符计数也不能替代模型服务的输入、输出 token 限制。

原生 reasoning 的供应商续接字段属于实际请求内容，在消息投影之前附加并计入字符预算。它在进程内保留，与可核对的研究进展分开；日志保留模式、长度、用量与请求摘要。重载后没有私有数据或必要推理历史无法容纳时，明确依据原问题、研究进展和执行事实重建输入，并保留稳定快照及回查入口。恢复目录最多列出三份资料，每份附实际小节数量、前八项原始标题与读取动作；完整目录可按入口获取，标题与目录不算正文交付。最新完整工具结果组优先保留，成功的进展保存由最新状态表达，失败的保存结果仍进入恢复输入。较早正文使用带原范围的恢复摘录；预算不足时先移出这些摘录，列出未展示资料的入口，再复用整批分配器裁剪最新正文，更新实际范围、引用和续读游标。必要状态与导航仍放不下时暂停。恢复附带的正文只在实际交付后计入已读范围；重建后的长任务质量需要验证。

默认运行和后续能力验证保持 reasoning 开启。发生偏差时，先核对某次实际输入、可用工具、资料范围、保存进展与后续行动；固定模型模式比较 harness 的信息交付改动。输入确有歧义和模型单独误读分别记录，行为对照不能自行证明私有推理如何强化某个前提。开关对照保留诊断价值，不能作为默认开启的验收门槛。

120,000 与 240,000 字符可作为实验基线，不能解释为 token 容量。单次窗口、整批份额、进展大小及整理阈值需要联合验证；目标包括减少遗漏和无增益读取，同时保留下一轮操作空间，不能只根据返回越短选择默认值。

## 7. Tavily 的使用与验证

截至 2026-10-01 核对的官方文档：[Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) 将 `max_results` 与每来源 `chunks_per_source` 分开，后者范围 1–3，适用于 `basic`、`advanced`、`fast`；[Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract) 支持 `query`，按问题相关性排列摘录，其 `chunks_per_source` 在提供 `query` 时生效，范围 1–5。当前已接入 Search 的可选片段数，省略沿用服务默认。小样本真实请求确认片段量有差别，尚未建立最佳默认值或稳定的任务收益；按问题 Extract 摘录尚未接入。

### 7.1 搜索交付

保留查询和来源限制的明确语义。模型通过查询表达信息缺口，Tavily 根据查询和参数选择候选及片段；模型此时没有指定页面中某个未知位置。harness 保存实际取得的片段，按返回顺序和明确的预算规则交付，不暗中改变来源排序或声称已选中最佳证据。

每个候选返回来源编号、该次获取的资料引用、标题、URL、内容类型和相关片段，帮助模型选择来源、改写查询或判断现有证据是否足够。同一来源再次出现时展示已有来源关联及新的查询结果，不让不同资料编号被误当成独立来源。只返回标题和编号不足以替代内容线索。片段预览被省略时提供续读入口；候选目录超过整批预算时，返回供 `list_documents` 使用的游标，固定到本次搜索的候选集合，并说明只展示了其中一部分。后续目录仍附短预览，模型可用资料引用展开片段。预览大小通过相关性判断和关键条件的实测选择。

返回状态区分“已有搜索片段”与“已有页面提取文本”。读取 `S1-R1` 这样的片段引用，只能展开已保存的搜索片段；读取已知 URL 取得页面后，会返回关联到同一来源的页面快照，例如 `S1-P1`。再次搜索可以发现其他线索，但不是打开该页面所必需的步骤。

模型结果只携带继续决策所需信息；完整请求参数、过滤计数和诊断细节留在执行记录。错误类别、空结果、来源限制和截断状态属于决策信息，需要保留。

第一阶段用少量固定查询验证 `basic` 下片段数 1、2、3 的实际行为；再以相同片段数比较 `basic` 与 `advanced`。后续选择默认值以及是否让模型控制深度，依据关键条件保留、来源覆盖、费用和延迟，不按“返回越少越好”选择。

### 7.2 相关摘录与完整提取

已有 `page_text` 时，优先在该快照中定位并展开。尚无合适文本时，可以按具体信息缺口请求相关摘录，也可以直接提取页面文本。

带 `query` 的 Extract 结果保存为 `query_excerpt`，记录对应查询和来源。它与 `page_text` 分开登记，例如同属 S1 的 `S1-E1` 与 `S1-P1`；摘录不覆盖已有页面快照，其范围只指向摘录自身，也不能据此重建完整页面的小节边界。Tavily 若没有提供原文位置，系统不伪造对应偏移或小节引用。后续取得 `page_text` 后，通过实际文本匹配或查找重新定位；不能确认对应关系时如实保留不确定性。

第一阶段继续保持 `read_page` 原有获取语义，先完成正文回查基础，并通过独立探针核实新参数。相关摘录在第三阶段按上述语义接入正式工具，避免把现有“页面续读”改成不同查询摘录之间的拼接。

## 8. 持久化、旧会话与接口迁移

资料可见的时机必须与执行记录提交一致：持久会话完成落盘后，工具结果中的资料编号才作为已保存引用交付。获取后写入失败沿用存储故障停止规则；恢复不会重复执行已确认的外部调用，也不自动重跑结果未知的调用。

第一阶段可从现有版本 1 的记录重建来源与正文索引，不重写旧 JSONL。续读记录复用对应快照；再次获取到相同文本时仍保留各次获取事实，不因内容相同而丢掉查询或时间差异。来源、资料、小节及命中引用需要稳定映射到已提交记录与范围，游标也需能在重载后定位原阅读目标。

小节索引的解析规则版本及编号到范围的映射是恢复约定的一部分。可以保存已解析索引，或保留可重建它的确定版本规则；升级解析器不能改变已经交付的小节引用。重载验收既检查正文相同，也检查来源关系、小节边界及续读位置相同。

从旧记录重建索引，不代表所有新增数据都能直接写入旧格式。第一阶段的实际交付记录就需要明确持久结构、格式版本与读取兼容性；新进展和检查点的持久结构在第二阶段开始前定稿。旧格式中的笔记保持其原有语义；未知记录种类仍然报错，不以忽略未知数据的方式继续执行。

工具定义和系统提示变化会触发现有恢复配置校验。旧任务可以读取已保存资料，但不能把它静默续接为另一套工具协议。当前模型调用 `read_page(url)` 获取新快照；已有资料用小节、命中或资料编号在本地读取，常规续读使用返回的 `continuation`。获取层保留旧字符读取实现以解释原记录和内部缓存；模型工具不再接受 `read_page(start)`。旧字符参数不重新解释为小节编号、行号或另一份文本的位置。

## 9. 实施顺序与验收

### 第一阶段：正文可定位

交付来源关联、资料与小节索引、稳定引用、资料目录、页面概览、字面查找、按节或命中阅读、普通正文续读，以及本轮实际交付记录。将搜索与页面结果接到这条链路，默认由程序处理阅读范围和单次分页。精简的阅读视图仍保留选择线索，底层资料可继续读取；同步外置提示中的正文入口，保留旧接口的兼容含义。

复用现有 Session、检索与上下文测试，新增保护以下行为的用例：

- 同一来源的多次搜索和页面提取保持关联，不同来源不因标题或域名相同被合并；查询和获取时间仍可区分。
- 搜索片段与页面提取文本均可直接读取；正文范围不含事件 JSON；多次阅读复用同一快照，不重新登记页面或拼接重复正文。
- 搜索返回保留选择来源的片段线索，省略与候选分页明确；展开搜索片段不会冒充已取得完整页面。
- 重新抓取、续读、重载后，旧资料、小节和游标仍定位对应文本；遮蔽、换行处理和解析器版本不导致位置漂移。
- 资料目录可发现早期资料；小节名称、层级和边界来自实际文本。同名标题可通过路径与引用区分，代码块伪标题被排除，无可靠结构时保留普通阅读入口。
- 读取小节无需模型指定长度；整节可容纳时完整返回，过长时按预算分页。父节包含子节，续读不越过目标边界；最后一页不误标为本次返回整节。
- 无标题、超长段落、表格或代码块仍可连续读取，分段有明确标记和前进位置；换页预算变化不跳过正文。普通分页可在远离上下文硬上限时发生。
- 查找命中可直接展开或按所属小节读取；未命中、部分查找与非法引用均有明确结果，不扩大为关于整页或现实事实的否定结论。
- 上下文整理后，交付记录能复核模型请求实际包含的概览、片段和范围；已取得但未展示的正文不误标为已交付。
- reset 前资料不可读；失败任务资料带状态；存储失败和未知工具结果沿用现有恢复约束。
- 真实模型能根据搜索片段选择相关来源，再按小节或命中读取、使用返回游标继续，识别分页后的限定条件，并给出有原文支持的回答。离线通过与模型行为验证分别报告。

本阶段可以验证 Tavily 参数机制，但不更改未经对照选择的正式默认值。阶段完成只表示资料定位与回查链路交付，长任务进展保留仍由第二阶段解决。

### 第二阶段：研究可持续

交付研究进展更新、检查点、软阈值整理及恢复后的上下文重建。将新状态与旧 think 能力统一为清楚的工具契约；明确每次整理如何计入原有调用预算，以及低预算时怎样保存成果并结束。

使用固定资料对照“主动更新进展并在整理前补检查点”与“阶段性摘要”，其余模型、目标、资料与预算保持一致。比较早期发现保留、限定条件、引用有效性、事实回查和额外调用成本。自主轨迹分叉后不再声称两组请求完全相同。

核心验收是：八章汇总在多次整理后仍覆盖八章及出处；早期关键条件在回答时保留或被准确找回；错误笔记能通过原文核对修正；连续回读不再因永久豁免而累积；状态更新失败或中断后恢复一致。

### 第三阶段：检索更有效

正式接入选定的 Tavily 参数与相关摘录路径，核实摘录和页面快照的来源关联、类型与范围互不混淆，完善跨调用重复展示处理和整批交付预算。固定前两阶段的资料与上下文机制，逐项比较参数和交付策略，再选默认值与模型可控项。

先在固定查询中观察参数对结果的影响，再在代表性研究任务中核对最终答案。实测分别记录正确、遗漏、错误与无法核实的事实，以及来源覆盖、token 用量、工具调用、费用和耗时。减小返回量或正常结束均不单独构成通过。

### 决策依据与效果如何验收

每阶段同时检查程序契约、模型行为和任务结果。程序测试证明位置、内容、分页与交付记录是否准确；真实模型评估检查它能否利用这些信息选来源、定位并查证；最终答案再与原文逐项核对。三个层次分别报告，不互相替代。

针对关键一步，保存用户目标、该轮实际请求、模型选择的工具与参数、工具取得和交付的结果，以及后续发现或答案。判断选择时，只使用选择之前已送入模型的线索，不能用后来取得的答案倒推该选择本来就有充分依据。简短的目标说明可以帮助解释行动，但自述理由合理、调用合法都不能独立证明有效。

有针对性地比较：来源关联能否避免把同页资料当成独立来源；相关片段能否区分标题相似的候选；目录与按节读取能否帮助找到长文中部或小节末尾的限定条件；无目录、词形或语言不匹配时能否换词或续读；上级导言或交叉引用包含条件时是否会继续核实；重复资料退出上下文后能否重新识别与读取。对照固定共同资料、模型和预算，每次只改变一个待检验因素，例如保持目录相同，比较按节读取与手填范围的使用效果；后续自主轨迹分叉分别记录。

评价一次操作的效果时，查看是否取得目标事实或条件、发现冲突、在明确范围内排除线索，或为下一步提供了可用位置。空结果也可能帮助调整查询；连续重复同一范围且没有新线索则需要检查是否浪费调用。记录各项事实的正确、遗漏、错误和无法核实，以及总成本；不用“每次调用都必须成功”作为通过标准。少量样本支持机制判断，不宣称每次决策都恰当或所有任务都有收益。

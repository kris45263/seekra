# 模块与数据约定

业务模块位于 `src/seekra/`，使用包内相对导入。`seekra` 和 `python -m seekra` 共用 `seekra.cli:main`。安装、配置与会话命令见 [README](../README.md)。CLI 负责入口和交互，研究决策由执行核心负责。

## 搜索闭环

```text
用户问题 + Session 已完成历史
→ 创建任务并记录执行状态
→ 投影本轮上下文，DeepSeek 读取消息和工具定义
→ 生成工具调用或直接回答
→ 执行工具，记录结果并投影为 tool 消息
→ 下一轮模型决策
→ 完成答案落盘后更新完成对话视图及页面缓存
```

模型根据当前信息缺口选择工具或回答：需要发现来源时搜索，已有目标 URL 时可直接读取，信息足够时结束。DeepSeek 内部 thinking 模式当前关闭，think 工具记录的是显式研究笔记。

## 工具接口与研究工具

### tavily_search(query, max_results=3, include_domains=None)

使用 `basic`，模型可选择 1–10 条候选，省略默认 3，不请求 raw content 或 provider 生成的答案。可选 include_domains 最多 10 个域名，空列表或省略不限制；仅接受明确 ASCII 主机名，不含协议、路径、IP 或通配符，规范化空白/大小写并去重。有域名时明确发送 include_domains_mode=filter，不自动退回全网。返回 query、results[{title,url,content}]、processing 和实际 search_parameters；API 失败也保留有效请求参数供核查。参数不合法在联网前作为 invalid_arguments 回传模型。

数量和域名由模型通过工具参数选择；参数可用不保证选择最优。普通显示直接使用 provider 标题和 URL，模型历史与内容不因显示清理而改变。标题和链接在显示副本中遮蔽配置密钥及终端控制字符，原始正文不做语义去噪。

`retrieval.py` 中的 `normalize_search_results()` 显式校验原始返回；TypedDict 只是结构声明，本身不提供运行时校验：

- 顶层必须是对象，results 必须为列表。
- 无效 URL、非字符串正文/标题、空正文会被排除。缺失、null 或空标题用 URL 代替。
- 只整理首尾空白和换行，不删除导航、不改写正文、不摘要。
- 单次搜索内，整理后的 URL 和正文均相同才去重，保留第一次出现的顺序。同 URL 不同片段保留。
- 不合并 www、不删除查询参数，不做跨轮次去重或重复搜索惩罚。
- 坏条目只记首个排除原因，有效条目不受其他坏条目影响。

### read_page(url, start=0)

通过 Tavily Extract 的 `basic` 提取指定 URL，返回 Markdown 文本，不搜索替代页面，不调用摘要模型。读取公开 HTTP(S) 文本网页，不支持登录、点击操作或本地文件。

- `start=0` 重新请求该页面，并在当前任务的页面缓存中保存内容快照；工具完成记录同时保存快照变更。
- 每次最多返回 24,000 字符；长页面给出 `next_start`，模型可用同一个 URL 和该起点继续读取。
- 续读使用同一快照，不重复联网。结果包含 `snapshot_id`、`start/end`、总字符数及下一起点。
- `success` 代表本次返回全部已提取文本；`partial` 代表只返回该快照的一段。最后一段也仍是 partial，只是 next_start 为空。
- 请求地址和服务报告地址分别保留；Extract 没有提供可核实的最终重定向地址，`final_url` 为 null，不从报告地址猜测。
- 返回全部提取文本不等于网站全文完整无缺。网页未记载也不等于现实中不存在该事实。
- 新读取失败时不保留当前输入中的旧快照供续读；整次输入失败时完成历史不变，但任务记录保留已取得的快照供显式恢复。
- 地址校验阻止本地文件、凭据 URL、localhost 和非公网 IP 字面量；这是请求形式校验，不是对 provider DNS 或重定向行为的安全认证。本机代理 DNS 不参与 provider 地址校验。

### think_tool

默认参数为 `reflection`，记录模型显式笔记。返回 `content_kind=model_note`，不是新增外部证据。

可用独立实验开关切换结构：

```powershell
uv run seekra --repl --verbose --structured-think
```

实验字段为 `goal`（当前目标）、`observations`（实际观察）、`assessment`（判断与不确定性）、`next_step`（下一步及希望获得的信息）、`references`（已有搜索/读取的 tool_call_id，可为空）。只检查引用操作存在，不认证引用内容是否支持判断。失败操作也可以作为“尝试失败”的观察引用。模型仍可不调用 think 直接回答。

结构化模式已完成真实调用验证，但尚未证明普遍提升答案质量，因此默认关闭。

## 操作结果与显示

研究工具共同返回 `operation`、`status`、`content_kind`；具体内容由各工具提供。

|状态|含义|
|---|---|
|success|取得本次操作预期的数据或保存笔记；不表示结论已核实|
|empty|搜索正常完成但无命中|
|partial|读取返回了提取快照的一部分|
|failed|请求失败、数据不合法、提取失败或所有搜索条目被排除|

失败包含 `error_code` 和可读 `error`；API HTTP 状态与 provider 报告的页面失败原因分别表达。404 等可识别原因会保留，未知原因不猜测。认证错误正文和请求头不回传。

普通界面向 stderr 显示“正在思考/搜索/读取网页/整理信息”等简短状态；`--verbose` 额外显示轮次、参数、实际结果、读取范围、结果写回和预算。正文增量写 stdout，模型工具前说明也会显示，不在完成后重复输出。内部工具 JSON 不进入普通正文，隐藏 reasoning_content 不展示。详细调试显示副本遮蔽 API key，stdout 正文保留原文。

`deepseek.py` 使用同步 SSE 接收，按工具 index 累计独立调用，完整 finish_reason 和 DONE 后校验所有调用，再交给 `agent.py` 依次执行。流式消息不逐片写入历史。无工具流式验收脚本与主 Agent 共用该接收器。模型响应完成事件先结束正文行，再显示工具状态；每个完整步骤立即保存；只有成功答案更新完成对话视图。

工具 id/type/name 必须保持一致，arguments 字符串累计后交给 execute_tool 解析；整轮所有调用结构通过校验后才执行第一个工具。正常结束为 stop 且正文非空、无工具，或 tool_calls 且工具完整。缺 DONE、截断、协议异常或网络中断均失败，不自动重试、不退回非流式。

run_agent 的 on_content 回调逐段通知正文，on_event 通知模型/工具生命周期；函数返回完整最终答案。不传回调的程序调用者可以只消费返回值。CLI 正常执行时消费正文回调；恢复已保存答案且没有新流片段时才输出返回答案。已显示文字无法撤回，stdout 重定向可能保留工具前说明或失败残稿。

终端展示统一由 CLI 创建的 `AgentDisplay` 接收这两个回调；普通状态、verbose 诊断、计时与换行顺序都在 `display.py` 中处理。`run_agent` 不接收 `verbose` 参数，也不创建终端输出器；程序调用者需要详细终端展示时，创建 `AgentDisplay(verbose=True, secrets=...)`，传入它的 `content` 和 `event` 方法。实验采集器可独立接收 `on_event`，不必启用终端展示。诊断流与正文输出的异常边界见下文“展示与执行错误”。

“正在思考”是界面状态，不能推断模型启用了 thinking。verbose 的首段正文时间从本轮模型调用事件到首个含非空白字符片段写入并 flush 后计算，是显示提交时刻的近似值，不是精确屏幕渲染时刻；总耗时包含等待与接收，片段数单位为段，不等于 token 数。

检索与笔记策略的实验依据见 [研究发现](research-findings.md)，验证方法和证据边界见 [验证指南](validation.md)。

## 执行核心与模型接口

`execute_run` 接收 Model、ToolRegistry、Session 和取消令牌，返回 RunResult（run_id、status、answer、error）。配置冲突和存储不可用可直接抛出；普通执行错误同时记录并通过结果返回。`run_agent` 提供 DeepSeek 参数入口，成功返回答案字符串，失败抛出执行结果中的 cause。

Model.generate 接收本轮消息、工具定义、正文及 usage 回调和 CancellationToken，返回 ModelResponse。DeepSeekModel 使用原 SSE 接收器，归一化用量；原始网络协议和凭据不进入执行核心。ToolRegistry 以定义和执行函数注册工具；执行核心不根据工具名分派业务。

|模块|职责|
|---|---|
|agent.py|任务生命周期、预算、上下文请求、工具执行次序、恢复位置|
|models.py / deepseek.py|模型适配、usage 归一化、SSE 组装及连接释放|
|runtime.py|Model、ModelResponse、RunResult、CancellationToken|
|session.py|追加记录、重载投影、文件锁和会话列表|
|context.py|上下文大小控制、历史索引与原文引用|
|tools.py / retrieval.py|工具注册、参数校验、Search/Extract 与页面快照|
|display.py / cli.py|终端呈现、会话选择、用户操作|
|input.py|持续编辑区、粘贴解析、发送边界与串行任务调度|

## 会话记录与恢复契约

默认 CLI 在启动目录 `.seekra/sessions/` 自动保存；Python `Session()` 仍为内存会话，显式 `Session.create(directory)` 创建持久会话，`Session.load(path)` 重建。持久格式为版本 1 的 JSONL，每条记录有递增字符串 id、kind、UTC time。恢复时按记录顺序重建会话视图。

- run_started 保存问题、系统说明及模型/工具/提示词身份。
- model_started 计入累计请求次数，model_usage 保存本次最新累计统计。
- model_completed 只保存校验完成的 assistant 消息。tool_started 在调用前保存，tool_completed 保存结果及变更的页面快照。
- run_ended 区分 completed、interrupted、failed、paused、needs_attention，并可保存失败前已显示正文；残稿不作为正常 assistant 消息恢复。
- messages/pages 是已完成对话的兼容视图；仅最近任务保留完整运行视图，旧任务保留元数据和原始 records，避免每项任务都复制全部历史。新问题只继承完成视图。显式恢复仅针对最近任务，不回放已确认工具结果，不恢复半截 SSE。
- 失败、取消任务的原始记录仍可在同一对话内主动回读，但不会自动继承。`Session.clear()` 追加 reset，清空完成视图、页面缓存和可恢复任务，并禁止历史工具索引或读取 reset 及其之前的记录；磁盘原始数据保留，重载后仍执行同一边界。CLI `/new` 创建另一个 Session，旧会话文件仍可由用户显式打开。
- 模型身份、工具定义（包括描述）或系统提示模板改变时拒绝续接旧任务；凭据更换不影响任务身份。可使用原配置恢复，或在同一会话提交新问题。
- 已开始而没有结果的工具操作标记 needs_attention，禁止自动重跑；需要核实后提交新问题。当前工具以读取为主，未来外部写操作也不能用会话回退掩盖实际副作用。
- max_iterations 是任务累计请求上限，包括失败尝试。续接不自动重置；暂停后可显式提高总上限。
- 完整最终消息已保存但进程未写完成标记时，恢复只补完成状态，不重新请求模型。

运行期间使用进程内锁及操作系统文件锁。过期 Session 对象不能覆盖新记录。写入采用 append、flush 和 fsync；存储失败立即停止后续追加和执行。加载发现不完整末行时只恢复完整前缀；下一次取得排他锁后先另存残片再修复尾部。完整行损坏或未知格式版本拒绝加载。没有服务端事务承诺：工具副作用到结果落盘之间仍可能存在结果未知区间。

原始认证头从不写入记录，隐藏 reasoning_content 不持久化。标准 run_agent 入口绑定当前密钥遮蔽，磁盘副本中意外回显的配置密钥被替换；因此包含密钥的输入在重载后可能与现场内存不同。自定义 execute_run 调用者应为 Session 配置相应的 secrets。会话是本地敏感运行资料，默认被 Git 忽略。

## 上下文投影与历史读取

默认 `max_context_chars=120000` 限制序列化后的消息和工具定义字符数，是本地大小控制，不是 tokenizer 计算或模型窗口容量。

内容未超限时原样提供完整消息；超限时长工具正文转为短原文预览和记录编号，再以用户问题为起点整组移出最早的旧任务。每组包含该任务全部模型决策、工具调用和结果及最终回答，避免删除问题却保留依赖它的回答。当前任务的消息关系全部保留，只允许工具正文外置；历史回读结果不会再次转为引用。如果当前任务与工具定义仍超限，则 paused，需要提高上限或提交新问题。移出历史不生成摘要，模型仍可能需要回读更早任务才能理解跨任务指代。

`list_history(cursor=0, limit=20)` 浏览当前对话记录索引，`read_history(record_id, start=0, limit=24000)` 分段回读记录。只能读取当前 Session 最近 reset 之后的编号，不接受文件路径。结果附原任务的问题与该任务当前状态；索引中的问题最多显示 120 字符，原始问题可按 run_started 记录回读。读取结果属于历史资料，失败残稿不是已完成回答，模型笔记不因此成为外部证据。索引和读取都计入普通 Agent 迭代预算。

投影按消息计算序列化长度、增量扣除移出的任务，最终只深复制选中的消息；历史索引从游标开始取一页。这减少了反复复制、编码和全量索引分配，但不是总内存上限：records 仍在内存，加载和会话列表仍重建完整会话。上下文字符预算不能用来证明长会话的本地成本有界。

## 展示与执行错误

`on_event` 是状态观察者。普通异常会写入一次 `observation(display_error)` 并停用该回调，研究继续；异常不会进入正常模型消息。执行期间的 `KeyboardInterrupt` 按取消处理，start 回调也在生命周期异常边界内；完成后的通知单独处理，见下文。

正文通过 `on_content` 传递；写入、刷新及模型响应后的补换行失败使用 `ContentOutputError`，执行记录标明 `output_error`，不当作状态诊断忽略。未完成片段仅留作残稿；如果完整最终响应已落盘，恢复不重复请求模型。原异常保留在异常链中。

报告执行失败时再次发生的输出或取消异常单独记录，不覆盖最初的失败原因；若此时连诊断记录也无法保存，则仍按存储失败直接停止。

`final_answer` 只通知已完成结果，不承担正文传递。它在答案与 completed 状态落盘后触发；回调抛出的 `ContentOutputError` 或 `KeyboardInterrupt` 只追加 observation，返回值和完成状态保持成功，CLI 不因此报告失败或建议续接。完成之前的正文传递和补换行异常仍按失败或取消处理。通知诊断本身写盘失败仍向外传播，不伪装存储成功。

模型异常终止当前执行；工具返回的结构化错误结果供模型决定后续行动，工具抛出异常且结果未知时为 needs_attention。存储失败直接抛出原始错误并停止，不再尝试追加结束状态，因此磁盘记录可能停在 running，重新打开后按实际已落盘事实恢复。

## 取消与用量

交互输入使用 prompt-toolkit 的持续 Application；模型和命令处理在单一后台任务中运行，输入区不在生成期间退出。BracketedPaste 事件直接插入草稿，按键 Enter 才触发提交；运行期间 Enter 不创建排队任务。输出通过 display 写入线程安全的屏幕日志转接器，stdout 重定向时仍写入实际正文目标。启动或切换会话时从执行记录重建问答与未完成片段，替换对话区；新建会话清空对话区。屏幕滚动区限制为最近 20 万字符，不影响模型消息或会话原文。窗口结束会请求取消并等待当前处理器退出，不强行终止线程。

换行处理兼容 Ctrl+J、常见 Shift/Ctrl+Enter 序列。Windows VT 输入启用 win32-input-mode，先解码包含修饰键的按键记录，再由 VT 解析器处理文字、粘贴及鼠标序列；退出时关闭该协议并恢复原控制台模式，不改用户终端配置。粘贴依赖标记而非输入速度。两块文本区按显示行滚动，流式追加保留非底部的阅读位置。非交互 stdin 只在 EOF 时提交整段文本。

CancellationToken 支持显式 cancel/check；模型适配器在流接收边界检查，并登记已取得的响应以便取消时关闭。Ctrl+C 仍通过同步调用栈传播。连接尚未建立或工具 HTTP 阻塞时，程序化令牌取消可能等待调用返回或超时；不承诺瞬时中断。工具返回后发现取消时，先保存实际结果再停止。

usage 采用 provider 的 prompt_tokens、completion_tokens 和缓存命中字段；缓存分母为同次请求的输入 token。独立 usage 块及最终内容块均可识别，每次请求只累计最后一份统计。缺失和非法字段不填零；会话累计显示已报告部分及缺失次数。显示的输入占用属于最近已报告请求，不是下一次上下文预测，容量占用不由该用量统计推算。

## 关键设计理由

- 追加执行事实与完成对话分开，既避免未完成答案污染新问题，也保留恢复所需的错误和工具结果。
- 完整流响应校验后执行工具，防止残缺参数触发动作。
- 使用上下文投影和原文回读控制体积；不以模型摘要覆盖历史证据。
- 显示消费正文和事件；格式与诊断故障不改变实际模型输入。
- 使用简单 Python 与单 Agent，使研究流程集中在统一执行核心。

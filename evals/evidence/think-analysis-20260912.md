业务基线为 `2b962ff`，模型为 `deepseek-v4-flash`。实验使用已归档的真实 Python 文档快照，不重新抓取网页。生产源码不改动。原始回答保留，不认证其中所有细节。

## 问题与方法

历史结构化笔记曾将 snapshot_id 当作操作引用，再将工具名当作引用。需要区分：引用校验实现错误、正确 ID 的呈现不足、长上下文定位困难，以及模型输出随机性。

离线直接执行实际 think 校验：snapshot_id 和工具名均失败，实际 tool_call_id 成功，空列表也成功。未请求网络。这表明当前观察不是正确 ID 被校验器拒绝，也说明不能只看 success 统计引用选择质量。

引用定位重放的共同输入取自 [旧对照](think-pair-20260910.json) 中第一项结构化运行的首个请求。保留全部 6 条历史消息、24,000 字符页面片段、原始系统日期、schema 和问题，不先缩短正文，以免同时改变上下文定位难度。这个实验重放的是历史决策节点，不代表当天从零研究。

原始组三次先运行；正文编号组三次随后运行。后一组仅在已有工具结果 JSON 增加 `source_tool_call_id`，值与协议字段中的编号相同，保留 snapshot_id 和其它数据。每次实际发出请求均与预定请求断言一致。只采集下一次模型响应，用生产 execute_tool 校验 think；不执行后续研究。不据此推断最终答案改善。

## 不强制 think 的三组比较

为补足此前“必须先调用笔记”的限制，使用同一真实已完成 Session 与页面快照，新的共同问题不要求 think，仅要求必要时续读同一页、准确区分未记载与不存在和说明范围。

三种实验条件为：不注册 think_tool、注册自由 think、注册结构化 think。按无/自由/结构化/结构化/自由/无顺序，各两次。实验运行器仅替换注册的工具列表，仍调用生产 run_agent；系统提示保持相同，其中关于笔记的通用说明也不改动。首请求去掉 think 定义后，六组逐字段相等。各组历史和页面快照均独立深复制。

六次都直接调用 `read_page(start=24000)`，随后回答：每次两轮模型调用，一次快照续读，没有 think 调用、没有搜索或新 Extract 请求。包括种子历史的首段，实际覆盖提取快照 0–37718 字符。核心小节结论都指出未规定必须使用 mimalloc，没有明确声称现实中不存在该要求；部分回答仍有语言混杂、解释冗余或对“并非强制”的推导措辞，不能把核心通过当成逐句无误。

这表明在“只需续读一次明确页面”任务中，不调用 think 也能完成核心目标；可用时模型并未主动选择它。因为自由/结构化两组实际未使用 think，这不是“使用 think 与不使用 think”的最终效果对照，更不能证明复杂研究中笔记无用。与 2026-09-10 强制调用实验相比少一轮，但两次实验日期、问题要求不同，不可据轮数比较作因果结论。

证据：[三条件六次完整请求、工具结果与答案](note-choice-20260912.json)。执行脚本：[自主选择对照](../../scripts/probe_note_choice_20260912.py)。

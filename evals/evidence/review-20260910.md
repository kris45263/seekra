操作引用失败有确切对象：正确 tool_call_id 是 `call_00_VD0Ot7Pmp8h6LSom2ait9349`，模型首先填入的 `b76485fd1b4dad30` 实际是 snapshot_id，第二次填 `read_page`。这两次错误是模型参数选择失败，校验按当时规则正确拒绝；本组实验不能区分 ID 可见性、字段说明、长上下文定位与模型随机性。后续固定请求的引用定位对照见 [2026-09-12 实验](think-analysis-20260912.md)。

## F1：复杂题必须保留的具体问题

问题原文：根据 Python 3.13 官方文档，mimalloc 在普通 GIL 构建与 free-threaded 构建中的启用条件分别是什么？捆绑、默认使用和必须使用是否相同？请提供官方来源，不要混用其他 Python 版本。

本轮实际做了两次搜索、五次 read_page、两次自由 think。memory 快照完整两段读取；free-threading 页读取 10012 字符；configure 只读 0–48000 / 56562，尚有 8562 字符未返回。

已改善/做到：模型识别搜索里有 3.14 片段，主动读取 3.13 页面；最终把构建可用与运行时默认区分开，没有简单以“enabled by default”直接证明运行时默认使用。

仍存在的问题：

1. **从局部证据扩大为整个文档集合的否定。** 答案多次说“3.13 官方文档并未写出……必须使用”，但只核查了少数页面，configure 甚至未读到快照末尾。这些证据不能证明整个版本文档中不存在该表述。无需先判定真实 mimalloc 行为，也能判定这个归纳超出了已获取证据。
2. **引用内容与支持主张不完全对应。** 开头用 configure 的 “Disable … enabled by default” 支持“随源码捆绑”；这条引文本身只说明开关和默认支持状态。捆绑应对应实际搜索中取得的 What's New 相关说明，不能把相邻事实都归给同一引文。
3. **把表格范围误说成环境变量全部取值。** 答案声称 `PYTHONMALLOC` 取值“只有 pymalloc/malloc 系”，但工具正文图例同时列出 mimalloc。至少存在内部证据解释不一致；不据此延伸断言所有运行时行为。

下一次有效对照应针对上述一种错误：固定真实请求和已取得证据，检验模型能否约束主张范围，或补入精确版本来源后是否纠正。不要以“再问一次复杂题正常结束”当作修复，也不要只用新提示词同时改变多个因素。

证据：[boundary 原始请求、工具正文与答案](boundary-20260910.json)、[指定页用例](page-20260910.json)。

## E1：Extract 成功但请求目标不匹配

原路径 `/mini-core-nonexistent-20260908`，新增不同路径 `/seekra-nonexistent-20260910`；正常对照为 `/zh-cn/guides/vision`，另读取站点首页 `/`。

- 本机 HTTP：正常 Vision 页 302 到带尾斜杠地址，最终 200、标题为图像理解。两个缺失路径均直接 200、无 HTTP 跳转，标题为 Your First API Call；两者与首页的 HTML 字节哈希完全相同。
- Tavily basic：两个缺失路径各请求两次，四次均返回 4131 字符、相同文本哈希、入门页内容，报告 URL 仍是所请求的缺失路径。正常页返回 12477 字符，首页返回 5459 字符；缺失路径与首页提取格式并不完全相同。
- 本地 read_page：按当前“取得非空提取文本”规则判 success，内容保留入门页；没有本地替换成其他页面的证据。

支持的因果范围：即使绕过 Tavily，本次访问链路也会在未知路径返回首页 HTML，因此现象不是必须由 Extract 单独造成。更准确的描述是“站点或其访问链路对这些路径返回 200 首页回退，抓取成功却不满足用户目标”。本机可能经过代理/CDN，未取得站点服务端日志，不能进一步锁定源站路由、CDN 或代理；也不能凭重复哈希断定 Tavily 缓存机制。

下一步若要设计目标匹配处理，应先确定如何识别预期标题/主题与通用回退内容的冲突，避免把所有 200 或非空正文认证为目标已核实。

证据：[HTTP 元数据、原始 provider 响应与 harness 结果](extract-match-20260910.json)，脚本：[Extract 探查](../../scripts/probe_extract_20260910.py)。

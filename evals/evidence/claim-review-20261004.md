# 原文条件、历史归属与逐项核对：本批实现和验证

实验记录日期：2026-10-04；说明核对日期：2026-10-05。按“静态判准 → 来源绑定 → 关键表述对照 → 观察停止与重复行为”的顺序执行。模型均为 `deepseek-flash`，reasoning 开启、effort 为 `high`、输出预算 8,192 token。未加入默认自动评审、固定决策次数或重复次数门槛。

## 1. 本批结论

- 稳定的任务、响应、当时进展和资料快照关联已经实现，并进入真实下一次模型输入。
- 20 个静态正反例、两次顺序打乱核对的 40 项分类符合预设判准；一条解释仍扩大了原文，不能把分类正确等同于审查理由可靠。
- 完整回答核对的四项有效运行，仍漏掉或保留已知的条件/归因问题。逐项表格有局部改进，没有证明额外审查值得默认启用。
- 两项部署核对都读取旧进展记录 14，正确承认当时保存过未知项。此观察支持入口可用，不证明归属错误已稳定消失。
- 本批共 30 次真实模型请求：静态核对 8 次，完整回答核对及失败运行 22 次。没有真实 Tavily 调用。

原始文件与哈希、分任务用量、读取覆盖和调用统计见 [汇总 JSON](claim-review-summary-20261004.json)。

## 2. 判准与静态正反例

[claim-boundaries.json](../claim-boundaries.json) 的 20 个案例来自已有 Meridian、Relay 虚构资料及实际历史执行反例。原文句子与既有保存文本核对；有限阅读场景另行明确标记。`expected/rationale` 只用于人工核对，没有发送给模型。

| 情况 | 应拒绝的表述 | 应保留的表述 |
|---|---|---|
| 对象范围 | 禁止共享访客，被写成非访客是必要条件 | 共享访客不可用；其他候选账户仍需核实 |
| 触发时点 | 连续离线 30 天后验证，被写成第 30 天前硬截止 | 忠实触发表述；明确标为建议的提前安排 |
| 未知依赖 | 每 28 天联网保证 45 天方案成立 | 明确说明重置机制未知的候选方案 |
| 通知时点 | 完成后通知，被加强成原文明确的立即/当天截止 | 完成后通知；立即作为避免遗漏的建议 |
| 补救与完成期限 | 事后批准保证补救；满 7 天检查被加强为明确完成截止 | 原前提未满足，补救未知；触发与完成期限分别说明 |
| 部分阅读 | 未读限制小节，却说整页没有限制 | 已取得片段支持什么、还有什么待读 |
| 历史事实 | 当前没有缺口，所以过去保存是虚构 | 根据旧任务已提交记录确认过去保存事件 |

分类为 `supported/conditional_advice/unsupported`，不是对模型全部建议作二元好坏判定。普通忠实意译、合理建议应允许；错误在于扩大限定、冒充来源要求、承诺未确认充分性，或混用不同任务的证据。

[静态核对记录](claim-calibration-20261004.json) 使用两次打乱顺序，每五项一次请求，8 次请求完成 40 项分类，无分类差异。检查公开解释时发现，第二轮 a4 正确拒绝“只要非共享访客就一定可用”，但理由把 after 30 consecutive offline days 写成“每 30 天在线验证”。这是理由里的新增周期解释，不算分类错误，另行保留为审查风险。

这是明确规则、单项表述的小集合，不包含模型自主提取完整回答的关键断言，也不涉及工具、搜索或上下文整理。不能据此得到生产环境审查准确率。

## 3. 已实现的历史核对入口

`read_history(record_id, view="review")` 接受 `model_completed` 记录，返回历史消息和 `origin`：

- 原任务编号、响应记录编号、时间、结束原因。
- 完整原问题的回读入口。
- 该响应产生前最后一次成功提交的进展记录及版本；没有则明确为 `null`。不使用新任务当前进展，也不使用旧任务之后的更新。
- 该任务此前获取/读取、或当时进展引用的资料身份、快照、原获取记录与读取入口。资料身份不会因同 URL 新快照而替换。
- 资料菜单最多八项，明确省略数量；其余可从当时进展引用或对应历史记录继续定位。

`list_history` 的模型消息条目和普通文本回读提供 `review_action`。核对视图按模型可见消息文本分页，`offset_basis=model_content_v1`；原有 `text/raw` 偏移语义保持。

这是一项导航和执行事实关联能力：当时已保存状态不等于当时实际收到全部正文；资料菜单不等于证据；历史模型文字也不认证事实。事实解释查正文，保存声明查当时事件，任务要求查原始问题。

[九项回归测试](../../tests/test_history_review.py) 覆盖：新任务隔离、同 URL 后续快照、失败保存和后续同任务更新、无进展、分页/重载/reset、参数边界、继承资料身份、资料数量边界，以及工具结果进入真实下一次请求但不冒充正文交付。

## 4. 完整回答对照与有效结果

复用已有两份真实错误回答及其完整执行记录，每次在独立新核对任务中运行。基础版本要求通过核对入口查原问题、正文和当时进展；对照版本只增加关键表述、原句/执行记录、支撑关系与未知依赖的表格要求。没有告诉模型具体错句或金标准。

重放旧记录后缺少私有 reasoning 续接，供应商业务上下文重建是预期机制。本实验属于显式历史核对，不是普通研究任务的定稿阶段。

| 用例与版本 | 有效运行 | 模型请求 | 新任务输入/输出 token | 观察 |
|---|---|---:|---:|---|
| Meridian 来源绑定 | [记录](claim-review-bound_review-meridian-20261004.json) | 5 | 65,619 / 6,686 | 读完保存文本，仍称“非访客类账户”为必要前提；修订后保留错误 |
| Meridian 加逐项对照 | [记录](claim-review-claim_comparison-meridian-20261004.json) | 6 | 72,910 / 7,068 | 回查当时进展 30，纠正“30 天内”措辞；漏掉必要账户范围，修订后仍保留 |
| Relay 来源绑定 | [重跑记录](claim-review-bound_review-relay-retest-20261004.json) | 4 | 41,232 / 6,993 | 读取进展 14，正确核对旧缺口；仍将“立即通知”归为原文硬要求 |
| Relay 加逐项对照 | [重跑记录](claim-review-claim_comparison-relay-retest-20261004.json) | 3 | 30,121 / 7,726 | 正确核对旧缺口及尚未触发事项；对照未覆盖“立即”这一加强，修订后仍保留归因风险 |

部署基础版本的 [首次运行](claim-review-bound_review-relay-20261004.json) 在首次请求发生连接错误，没有已确认响应及用量，不能解释为零消耗或能力失败。部署对照的 [首次运行](claim-review-claim_comparison-relay-20261004.json) 第三次请求输出未正常完成；之前已有两次完整响应，最终回答不计入质量结果。保持相同配置分别重跑，没有删除失败记录。

原始运行文件的 `usage` 是含旧任务的会话累计；表格和汇总 JSON 只统计新任务。每个案例/版本仅一项有效结果，重跑也不是统计重复。时间与 token 只解释该轨迹，不构成稳定成本差异。

### 关键漏判怎样发生在公开结果中

Meridian 的对照表核对了正确原句“共享访客不可用”，却未单列建议中的“非访客是必要前提”。于是表格几乎都通过，后面的完整修订仍复制该句。

Relay 的对照表核对了正确的“检查完成后通知”，却未单列“原文硬要求：立即通知”。修订保留了更具体的时点归因。立即通知本身可作为合理建议；这里记录的是其被归入原文硬要求的风险，不凭一个词否定全部解释。

这两项都提示：需要区分“正确原句被选中”与“实际有问题的每项断言都接受核对”。目前尚未证明如何稳定完成后者，不从这些公开结果推断模型私有 reasoning 的内部原因。

## 5. 停止、重复与读取范围观察

按工具名与完整参数规范化后，四项有效运行都没有完全相同参数的重试。游标分页、不同关键词和不同视图分别记录，没有用“同一页面又读了一次”直接判为循环。尚不足以制定阻止或提醒的可靠阈值。

Meridian 来源绑定版本本轮确认交付覆盖整份 13,522 字符文本；对照版本为 `[0,6059)` 与 `[13252,13522)`，中间尚未交付。对照仍认可“编号 0–119 全部相同”“全文没有例外”等完整核实表述，需要区分旧任务取得全文的历史依据和本轮实际复核范围。全局关键词查找可证明该字面查询的结果，不等于本轮顺序读完全部正文。

少一次调用不等于答案更好；多一次调用也不等于获得必要新证据。本批收集了归属、实际交付、工具动作与输出，不加入固定次数门槛。

## 6. 验证与剩余决策

工程检查：`uv run --locked python -X utf8 -m unittest discover -s tests -q`，248 项、247 通过、1 跳过；新入口九项通过，关键缺失行为先出现失败，再实现。工程结果不认证语义质量。

已实现且可维护的是来源绑定。逐项对照只作为实验要求，未加入正式系统提示或默认自动流程。当前证据不支持把额外评审当作可靠门禁。

下一项可检验假设是：先确保关键断言在其完整语境中被提取，再分别查支撑关系；否则仅要求表格会选择正确原句、漏掉嵌在建议中的扩大。需要允许正确意译与保守建议，并检查提取漏项、审核误判、修订新增错误和额外成本。这个假设尚未实现或验证，不能称为已确认修复。
